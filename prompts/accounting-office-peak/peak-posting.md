# ความรู้โดเมนที่ต้องเขียนลงใน skill

## ก. Step 0 — สำรวจ tool ที่มีจริง แล้วจับคู่งานเอง (จุดต่างที่สำคัญที่สุด)

เอกสารนี้ **ไม่ระบุชื่อ tool ตายตัว** เพราะชุด tool ของ PEAK MCP อาจต่างจากที่ทดสอบไว้
ให้เขียนเป็น **ตารางงานที่ต้องหา tool ให้ได้** แทนชื่อ tool:

| งาน | ต้องมี tool ที่ทำอะไร |
|---|---|
| ยืนยันกิจการปลายทาง | อ่านข้อมูลกิจการที่เชื่อมต่ออยู่ |
| ดึงผังบัญชี | list ผังบัญชีของกิจการนั้น |
| ค้นคู่ค้า | ค้น contact/vendor ด้วยเลขผู้เสียภาษีและชื่อ |
| ตรวจเอกสารซ้ำ | ค้นเอกสารค่าใช้จ่ายด้วยเลขที่อ้างอิง/ยอด/วันที่ |
| สร้างเอกสาร | สร้างเอกสารค่าใช้จ่าย |

**หา tool สำหรับงานใดไม่เจอ → หยุดแล้วแจ้งผู้ใช้ว่าทำขั้นนั้นไม่ได้
ห้ามข้ามขั้นนั้นแล้วบันทึกต่อ** โดยเฉพาะขั้นยืนยันกิจการและขั้นตรวจเอกสารซ้ำ

ยังไม่ได้เชื่อมต่อ/authorize MCP → แจ้งผู้ใช้ทำก่อน **ทำแทนไม่ได้**

## ข. Step 1 — ตรวจกิจการปลายทาง และเหตุผลว่าทำไมข้อนี้เข้มกว่าที่อื่น

อ่านข้อมูลกิจการที่เชื่อมต่ออยู่ แล้วแสดงเทียบกับ client-profile.md เป็นบล็อกชัด ๆ
(ชื่อ + เลขผู้เสียภาษีทั้งสองฝั่ง แล้วสรุปว่าตรงหรือไม่ตรง) — **ไม่ตรง → หยุดทันที**

ต้องเขียนเหตุผลไว้ด้วย: **PEAK ให้ผู้ใช้หนึ่งคนเข้าถึงหลายกิจการได้**
สำนักงานบัญชีที่ดูแลลูกค้าหลายรายจึงมีความเสี่ยงสูงที่จะบันทึกผิดกิจการ ข้อนี้ห้ามข้ามเด็ดขาด

แล้วดึงผังบัญชีของกิจการนั้นมาใช้จับคู่ — **ห้ามใช้ผังบัญชีจากลูกค้ารายอื่น**

## ค. Step 2 — คัดรายการและตรวจคณิตศาสตร์

คัดเฉพาะแถวที่ผ่านการตรวจ รายการที่ติด "ไม่พบเอกสาร" / "ต้องแก้" → ไม่บันทึก
แล้วรายงานแยกว่าข้ามกี่ใบเพราะอะไร

ตรวจทุกใบ: |ยอดก่อน VAT × 0.07 − VAT| ≤ ค่าคลาดเคลื่อน · ยอดก่อน VAT + VAT = ยอดรวม ·
**WHT (ถ้ามี) คำนวณจากยอดก่อน VAT ไม่ใช่ยอดรวม** — ข้อนี้ผิดกันบ่อย ต้องเขียนไว้ตรง ๆ

## ง. Step 3–4 — กันเอกสารซ้ำ แล้วกันคู่ค้าซ้ำ

เอกสารซ้ำ: ค้นด้วยเลขที่เอกสารของผู้ขายก่อน ไม่เจอให้ค้นด้วยชื่อคู่ค้า + ยอดรวม + วันที่
ซ้ำครบเงื่อนไข → ข้าม แล้วรายงานว่าซ้ำกับเลขที่เอกสารอะไรในระบบ

คู่ค้าซ้ำ: ค้นตามลำดับในค่าตั้ง **ห้ามข้ามขั้น** ·
เจอ 1 ราย → ใช้รายนั้น · เจอหลายราย → เลือกรายที่ข้อมูลครบแล้วแจ้งผู้ใช้ว่ามีซ้ำ ·
ไม่เจอ → ทำเครื่องหมาย "คู่ค้าใหม่" ใน preview ให้ผู้ใช้เห็นก่อนสร้าง

**ที่อยู่ต่างกันไม่ใช่เหตุผลให้สร้างคู่ค้าใหม่**

## จ. Step 5 — จับคู่รหัสผังบัญชีและประเภทภาษี (ต้องเลือกสองอย่าง ไม่ใช่อย่างเดียว)

ลำดับความสำคัญ: mapping-overrides.md ของลูกค้า **ชนะ** ผังบัญชีในไฟล์ของลูกค้า
ชนะผังบัญชีสดที่ดึงจากระบบ ชนะกฎ default
ความมั่นใจต่ำกว่าเกณฑ์ → ใส่เครื่องหมายเตือน + เสนอ 2 ตัวเลือกให้ผู้ใช้เลือก

`references/account-code-mapping.md` ต้องขึ้นต้นด้วยคำเตือนว่า **ผังบัญชีเป็นของแต่ละกิจการ
ไม่ใช่ค่ากลาง** ต้องดึงสดทุกครั้งและเลือกจากรายการที่มีจริง **ห้ามใช้รหัสจากลูกค้ารายอื่น
และห้ามสร้างรหัสใหม่** ตามด้วยลำดับความสำคัญข้างบนและกฎการเลือกตามประเภทรายจ่าย

`references/vat-type.md` ต้องมีตารางประเภท VAT: VAT 7% (ซื้อจากผู้ประกอบการจด VAT
มีใบกำกับเต็มรูป → เข้ารายงานภาษีซื้อ ขอคืนได้) · VAT 0% (เข้ารายงานแต่ไม่มียอดภาษี) ·
ยกเว้น VAT / ไม่มี VAT (ผู้ขายไม่จด VAT หรือได้รับยกเว้นตามมาตรา 81 → ไม่เข้ารายงานภาษีซื้อ)
พร้อมคอลัมน์ "ผลต่อรายงานภาษีซื้อ" เพราะนั่นคือเหตุผลที่ต้องเลือกให้ถูก
และวิธีตั้งค่าราคารวม/ไม่รวม VAT + บรรทัดชี้ไปกฎ VAT ฉบับเต็มใน plugin หลัก

## ฉ. Step 6 — Preview (บังคับ)

แสดงทั้งกองพร้อมกันเป็นตาราง: ลำดับ · ไฟล์ · คู่ค้า · เลขที่ · วันที่ · รหัสบัญชี · ประเภท VAT ·
ยอดก่อน VAT · VAT · WHT · ยอดจ่ายสุทธิ · สถานะ — ตามด้วยยอดรวมทั้งกอง

**ต้องถามผู้ใช้ 3 ข้อนี้เสมอ ไม่มีค่า default**:
- ราคาในเอกสารรวม VAT แล้ว หรือยังไม่รวม
- จ่ายเงินแล้ว หรือตั้งหนี้ค้างจ่าย
- ถ้าจ่ายแล้ว จ่ายจากช่องทางไหน — แต่ **ห้ามบันทึกการจ่ายชำระเอง** ถามไว้เพื่อบันทึกในหมายเหตุ
  ให้ผู้ใช้ไปบันทึกต่อ

ก่อนแสดงให้ผู้ใช้ ส่งตารางให้ผู้ตรวจอิสระก่อน แล้วแนบผลตรวจไปพร้อมตาราง
**ส่งให้แค่ path ของตาราง preview กับ path ของเอกสารต้นทาง
ห้ามส่งเหตุผลว่าเราเลือกรหัสบัญชีนั้นเพราะอะไร**

รอคำยืนยัน **ห้ามข้ามไปขั้นบันทึกเอง**

## ช. Step 7–9 — บันทึก สรุป แล้วตรวจซ้ำ

บันทึกทีละใบ เก็บเลขที่เอกสารที่ระบบออกให้และรหัสอ้างอิงที่ response คืนมา

**response ช้า หลุด หรือ timeout → ห้ามยิงซ้ำ** ให้ค้นในระบบก่อนว่าเอกสารถูกสร้างไปแล้วหรือยัง
หลักการ: **ไม่มีคำตอบ ≠ ไม่ได้สร้าง**

หลังบันทึกเสร็จ ต้อง **ตรวจซ้ำ**: ค้นเอกสารค่าใช้จ่ายในช่วงวันที่ของงวดอีกครั้ง
แล้วเทียบกับที่ตั้งใจบันทึก — จำนวนที่เพิ่มขึ้น · เลขที่อ้างอิงซ้ำ · ยอดรวมตรงกับ preview หรือไม่
ไม่ตรง → **รายงานตามจริง อย่าเดาว่าสำเร็จ**

## ซ. หัวข้อ "เมื่อเกิดข้อผิดพลาด" ต้องมีเป็นหัวข้อของตัวเอง

1. ไม่มีคำตอบ ≠ ไม่ได้สร้าง — ตรวจก่อนเสมอ
2. **หยุดทั้งกอง** เมื่อไม่มีสิทธิ์ หรือกิจการปลายทางไม่ตรง
3. **ทำต่อได้** เมื่อเป็นปัญหาเฉพาะใบ แต่ต้องรวบรวมรายงานตอนท้าย
4. ห้ามข้ามกลไกกันซ้ำเพื่อให้งานเดินต่อ
5. เจอรหัสข้อผิดพลาดที่ไม่รู้จัก → **แสดงข้อความดิบให้ผู้ใช้เห็น** แล้วหยุด อย่าเดาความหมาย

## ฌ. ตาราง subagent

ค้นเอกสารซ้ำ/ค้นคู่ค้า/ดึงผังบัญชีหรือยอด → subagent ที่มีเฉพาะ tool อ่านของ PEAK ·
ตรวจตาราง preview → ผู้ตรวจอิสระ · ตรวจความเสี่ยงภาษี → subagent ภาษี

ต้องเขียนหมายเหตุไว้ด้วยว่า subagent ค้นข้อมูลของ PEAK **ต้องเติมรายชื่อ tool อ่านก่อนใช้ครั้งแรก**
ถ้ายังไม่ได้เติม มันจะรายงานว่ายังตั้งค่าไม่เสร็จ — **ห้ามตีความว่า "ไม่พบข้อมูล"**
เพราะการสับสนสองอย่างนี้ทำให้เกิดเอกสารซ้ำ

2. **ห้ามสร้างคู่ค้าใหม่ก่อนค้นหาให้ครบทุกวิธี**
3. **ห้ามเดารหัสบัญชีหรือประเภท VAT แล้วบันทึกเลย** ต่ำกว่าเกณฑ์ → ถามผู้ใช้
4. **ห้ามยิงซ้ำเมื่อ response หลุด**
5. **ห้ามสร้างเอกสารสถานะอื่นนอกจากรออนุมัติ** และห้ามอนุมัติ/ยกเลิก/ลบ/ปิดงวด
6. **ห้ามบันทึกการจ่ายชำระ** แม้ผู้ใช้จะบอกว่าจ่ายแล้ว
7. **ห้ามใช้ผังบัญชีหรือรหัสบัญชีจากลูกค้ารายอื่น และห้ามสร้างรหัสใหม่**
8. **ห้ามเดาชื่อ tool** และห้ามข้ามขั้นที่หา tool ไม่ได้
9. **ห้ามบันทึกเมื่อกิจการปลายทางไม่ตรงกับ client-profile.md**
10. ข้อมูลถูกส่งออกไปยังระบบภายนอกผ่าน MCP — ผู้ใช้รับผิดชอบ PDPA และสิทธิ์เข้าถึงบัญชีลูกค้า

# หัวข้อที่ SKILL.md ต้องมี เรียงตามนี้

1. ชื่อ + ตำแหน่งในสายงาน + ต้องใช้คู่กับ plugin หลัก
2. กฎที่ต้องใช้วิจารณญาณ
3. ขอบเขต — รองรับเฉพาะเอกสารฝั่งซื้อที่ตรวจแล้ว / ไม่รองรับฝั่งขาย การอนุมัติ การจ่ายชำระ
   void ลบเอกสาร การแก้ผังบัญชี และการปิดงวด
4. ขั้นตอน Step 0 ถึง Step 9 (รวมขั้นตรวจซ้ำหลังบันทึก)
5. ตาราง subagent พร้อมหมายเหตุเรื่องการตั้งค่าก่อนใช้ครั้งแรก
6. หัวข้อ "เมื่อเกิดข้อผิดพลาด"
7. ข้อจำกัดและสิ่งที่ผู้ใช้ต้องตรวจเอง

หัวข้อ 7 ต้องพูดตรง ๆ ว่า: เอกสารอยู่ในสถานะรออนุมัติ ผู้ใช้ต้องตรวจและอนุมัติเอง ·
**skill นี้ไม่บันทึกการจ่ายชำระ** เพราะกระทบบัญชีธนาคารโดยตรง · รหัสผังบัญชีที่จับคู่ให้เป็นการอนุมาน
ต้องตรวจทุกใบ · ไม่ตัดสินรายจ่ายต้องห้ามตามมาตรา 65 ตรี และไม่ตัดสินสิทธิขอคืนภาษีซื้อ ·
**การกันซ้ำอาศัยเลขที่เอกสารของผู้ขาย — ไม่มีเลขที่หรือ OCR อ่านผิด การกันซ้ำจะไม่ทำงาน** ·
**ไม่แนบไฟล์เอกสารต้นฉบับ** ใส่ path ไว้ในหมายเหตุแทน · ยอดคงเหลือและรายงานภาษีต้องกระทบยอดเองอีกชั้น

## แบบฝึกหัดปรับแต่ง

| # | แก้ค่าตั้งเป็น | สิ่งที่ควรเห็น | บทเรียน |
|---|---|---|---|
| 1 | ระบุชื่อ tool ตายตัวทุกขั้น | skill จะพังทั้งตัวเมื่อ MCP เปลี่ยนเวอร์ชัน | ของที่ยังไม่ยืนยัน ห้ามเขียนเป็นข้อเท็จจริง |
| 2 | เปิดให้บันทึกการจ่ายชำระ | ต้องปฏิเสธ — กระทบบัญชีธนาคารโดยตรง | ขอบเขตของ skill ต้องหยุดก่อนถึงเงินจริง |
| 3 | ฐาน WHT เป็นยอดรวม | ตัวเลข WHT ผิดทุกใบที่มี VAT | ความผิดพลาดที่คำนวณลงตัวคือความผิดพลาดที่ตรวจยากที่สุด |
| 4 | ปิดขั้นตรวจซ้ำหลังบันทึก | ไม่รู้ว่าสิ่งที่เข้าระบบตรงกับ preview ไหม | งานที่ย้อนกลับยากต้องมีการยืนยันหลังทำ |
| 5 | ตัด reference ประเภท VAT | ไม่มีเกณฑ์เลือกว่าใบไหนขอคืนภาษีซื้อได้ | การเลือกที่กระทบรายงานภาษี ต้องมีกฎเขียนไว้ |
| 6 | ให้ใช้ผังบัญชีของลูกค้ารายก่อนหน้าได้ | ต้องปฏิเสธ | ผังบัญชีเป็นของกิจการ ไม่ใช่ของสำนักงาน |
| 7 | ให้ตีความว่า "ยังตั้งค่าไม่เสร็จ" = "ไม่พบข้อมูล" | จะเกิดเอกสารซ้ำทันที | สองสถานะนี้ต่างกันมาก แม้หน้าตาผลลัพธ์เหมือนกัน |

## กรณีทดสอบ

| กรณี | คำตอบที่ถูก |
|---|---|
| หา tool ยืนยันกิจการไม่เจอ | หยุด แจ้งผู้ใช้ ไม่บันทึกอะไรเลย |
| เลขผู้เสียภาษีกิจการในระบบ ≠ ใน client-profile.md | หยุดทั้งกอง |
| ยอดก่อน VAT 10,000 / VAT 700 / WHT 3% | WHT = 300 (จาก 10,000) ไม่ใช่ 321 (จาก 10,700) |
| ซื้อจากร้านที่ไม่จด VAT | ประเภท "ยกเว้น VAT / ไม่มี VAT" ไม่เข้ารายงานภาษีซื้อ |
| ใบกำกับอย่างย่อจากร้านสะดวกซื้อ | ต้องเตือนเรื่องสิทธิขอคืนภาษีซื้อ ไม่ตั้งเป็น VAT 7% เงียบ ๆ |
| ผู้ใช้ตอบว่า "จ่ายเงินแล้วจากบัญชีกสิกร" | บันทึกเป็นตั้งหนี้ + ใส่หมายเหตุ แล้วบอกให้ไปบันทึกจ่ายชำระเอง |
| รหัสบัญชีที่มั่นใจ 65% | ใส่เครื่องหมายเตือน + เสนอ 2 ตัวเลือก |
| subagent ค้นข้อมูลตอบว่า "ยังตั้งค่าไม่เสร็จ" | หยุดขั้นกันซ้ำ แจ้งผู้ใช้ให้ตั้งค่า ห้ามบันทึกต่อ |
| บันทึกเสร็จ 8 ใบ แต่ตรวจซ้ำพบ 9 ใบ | รายงานตามจริงว่าไม่ตรง ไม่สรุปว่าสำเร็จ |

สองกรณีท้ายคือเหตุผลทั้งหมดที่ skill ตัวนี้มีขั้นตรวจซ้ำและมีข้อห้ามเรื่องการตีความสถานะ
