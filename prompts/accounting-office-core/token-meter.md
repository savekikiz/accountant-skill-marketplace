# Prompt สร้าง skill `token-meter`

prompt นี้ใช้สร้าง skill วัด token และต้นทุนการใช้ Claude
ตัวจริงอยู่ที่ [`plugins/accounting-office-core/skills/token-meter/SKILL.md`](../../plugins/accounting-office-core/skills/token-meter/SKILL.md)

skill ตัวนี้ต่างจากทุกตัวในชุด เพราะงานหลักอยู่ใน **สคริปต์ Python** ไม่ได้อยู่ในข้อความ
บทเรียนของ prompt ตัวนี้คือ **อะไรควรเป็นโค้ด อะไรควรเป็นคำสั่งใน SKILL.md** —
งานที่ต้องคำนวณตัวเลขให้ตรงทุกครั้ง ควรเป็นโค้ด เพราะข้อความทำให้โมเดลคำนวณเองแล้วผิดได้

## ตัวแปรที่ปรับได้

| ตัวแปร | ค่าตั้งต้น | ปรับแล้วกระทบอะไร |
|---|---|---|

| แหล่งข้อมูล session | `~/.claude/projects/<project>/<id>.jsonl` (หรือใต้ `$CLAUDE_CONFIG_DIR`) | ถ้า Claude Code เปลี่ยนที่เก็บ สคริปต์ต้องแก้ |
| โมเดลตั้งต้นสำหรับคิดราคา | `claude-sonnet-5` | เปลี่ยนตามที่สำนักงานใช้จริง |
| ที่เก็บราคา | `references/pricing.json` (USD ต่อ 1M tokens) | แก้ไฟล์เดียวแล้วราคาทุกที่เปลี่ยนตาม |

| อัตราแลกเปลี่ยน | ไม่มีค่าเริ่มต้น (`--fx`) | ไม่มีค่าเริ่มต้นโดยตั้งใจ — ดูแบบฝึกหัดข้อ 4 |

## PROMPT — ก็อปทั้งบล็อกนี้

````text
คุณเป็นผู้เขียน Agent Skill ที่มีสคริปต์ประกอบ ให้สำนักงานบัญชีไทย

# งานที่ต้องส่งมอบ

1. `skills/token-meter/SKILL.md` — สั้น (ไม่เกิน 90 บรรทัด) หน้าที่คือ **บอกว่าคำถามแบบไหนใช้สคริปต์ตัวไหน
   และจะตีความผลอย่างไร** ไม่ใช่สอนวิธีคำนวณ
2. `skills/token-meter/scripts/tm_common.py` — โค้ดร่วม: โหลดราคา, จับคู่ราคากับ model id, คิดเงิน, นับ token
3. `skills/token-meter/scripts/session_usage.py` — อ่านการใช้งานจริงจาก transcript
4. `skills/token-meter/scripts/skill_footprint.py` — วัดขนาดของ skill เป็นชั้น
5. `skills/token-meter/scripts/count_prompt.py` — นับ token ของไฟล์หรือข้อความ
6. `skills/token-meter/references/pricing.json` — ตารางราคา

หลักการแบ่ง: **ตัวเลขและการคำนวณอยู่ในสคริปต์ · การตีความและคำแนะนำอยู่ใน SKILL.md**
ถ้าเขียนสูตรคิดเงินไว้ใน SKILL.md แล้วให้โมเดลคำนวณเอง ผลจะไม่ตรงกันในแต่ละครั้ง

`description` ต้องมีคำที่ผู้ใช้จะพูด: กิน token เท่าไหร่, ใช้ไปกี่บาท, skill นี้แพงไหม,
context เต็มเพราะอะไร, นับ token, token usage, cost report, เทียบต้นทุน skill, system prompt ยาวเกินไหม

# ค่าตั้งของงานนี้   ← แก้ตรงนี้

- มุมที่วัด: 3 มุม (การใช้งานจริงจาก transcript / ขนาดของ skill / ขนาดของ prompt หรือไฟล์ใด ๆ)
- ที่เก็บ transcript: ~/.claude/projects/<project>/<session-id>.jsonl หรือใต้ $CLAUDE_CONFIG_DIR
- โมเดลตั้งต้นสำหรับคิดราคา: claude-sonnet-5
- ราคา: references/pricing.json — USD ต่อ 1M tokens แยก input/output ต่อโมเดล
  จับคู่ key แบบ substring ของ model id (key ที่ยาวที่สุดชนะ)
- ตัวคูณ: cache_write_5m 1.25 · cache_write_1h 2.0 · cache_read 0.1
- โหมดนับ token: ถ้ามี ANTHROPIC_API_KEY ให้เรียก /v1/messages/count_tokens (exact)
  ไม่มีให้ประมาณจากจำนวนอักขระ (estimate, ±30%, ภาษาไทยคลาดเคลื่อนมากกว่า)
- อัตราแลกเปลี่ยน: ไม่มีค่าเริ่มต้น ต้องระบุด้วย --fx เท่านั้น
- ออก Excel: รองรับด้วย --xlsx (import openpyxl เฉพาะเมื่อใช้)
- Python: 3 มาตรฐาน ไม่พึ่ง dependency นอก stdlib ยกเว้น openpyxl ตอนออก Excel
- เกณฑ์คำแนะนำ: description เกิน ~150 tokens ให้ย่อ · SKILL.md เกิน ~5,000 tokens ให้ย้ายไป references

# ความรู้โดเมนที่ต้องฝัง

## ก. โครงสร้างการโหลด skill 3 ชั้น — เป็นแกนของ skill_footprint.py

- **L1 meta** (name + description) อยู่ใน context **ทุก session แม้ไม่เคยเรียกใช้**
  → ยิ่งมี skill เยอะ ยิ่งเสียทุกครั้ง นี่คือตัวเลขที่สำคัญที่สุด
- **L2 SKILL.md body** โหลดเมื่อ skill ถูกเรียก
- **L3 ไฟล์ใน references/** โหลดเมื่อ Claude เปิดอ่านจริง
- **scripts/ ที่แค่รัน ไม่กิน context** — กินเฉพาะ output ที่พิมพ์ออกมา

ข้อสุดท้ายคือเหตุผลที่ skill ตัวนี้เขียนเป็นสคริปต์ ต้องอธิบายไว้ใน SKILL.md ด้วย

## ข. การอ่าน transcript — เป็นแกนของ session_usage.py

- ทุกข้อความของ assistant ใน `.jsonl` มี block `usage` จริงจาก API — ใช้ค่านั้น ห้ามประมาณ
- ต้อง **ตัด entry ซ้ำที่เกิดจาก streaming** ไม่งั้นยอดจะเกินความจริง
- นิยาม **turn** = prompt หนึ่งครั้งของผู้ใช้ + ทุก API call ที่ตามมาจนถึง prompt ถัดไป
  (รวม tool call หลายรอบ) — ต้องเขียนนิยามนี้ใน SKILL.md เพราะผู้ใช้เข้าใจผิดบ่อย
- โหมด by-skill: นับ turn ที่มีการเรียก Skill tool หรือ slash command แล้ว **ยกยอดทั้ง turn ให้ skill นั้น**
  จึงเป็น "ต้นทุนของงานที่ใช้ skill" ไม่ใช่ขนาดของ SKILL.md — ต้องเขียนความต่างนี้ให้ชัด
- ตัวเลือกที่ต้องมี: เลือก session ล่าสุด / ระบุ session / ทุก session / กรองตามโปรเจกต์ /
  กรองตามวันที่ / แยกราย turn / รวมตาม skill / ใส่อัตราแลกเปลี่ยน / ออก Excel หรือ JSON
- หาโฟลเดอร์ไม่เจอ (เช่นรันในที่ที่ไม่มี transcript) → บอกผู้ใช้ตรง ๆ แล้วให้ชี้ไฟล์ด้วย `--path`

## ค. การตีความผลที่ SKILL.md ต้องสอนให้ Claude พูดกับผู้ใช้

- **cache_read มักเป็นตัวเลขใหญ่ที่สุดแต่ราคาถูก (~10% ของ input)** — อย่าให้ผู้ใช้ตกใจกับยอด total token
- **ตัวเลข USD คือราคาเทียบ API เพื่อดูขนาดงาน** ผู้ใช้แพ็กเกจ Pro/Max ไม่ได้จ่ายตามนี้
  ห้ามพูดว่าเป็นเงินที่จ่ายจริง
- โหมด estimate ต้องแจ้งทุกครั้งว่าเป็นค่าประมาณ
- คำแนะนำที่ลดต้นทุนได้จริง: ใช้ /compact หรือ /clear, ย่อ description, ย้ายเนื้อหายาวไป references/,
  ใช้โมเดลที่ถูกกว่าสำหรับงานซ้ำ ๆ

## ง. ข้อกำหนดด้านความปลอดภัยข้อมูล — สำคัญที่สุดใน skill ตัวนี้

ไฟล์ transcript มีบทสนทนางานลูกค้าอยู่ (ชื่อบริษัท เลขผู้เสียภาษี ยอดเงิน) ดังนั้น:

1. **ห้ามแสดงเนื้อหาในไฟล์ transcript** — รายงานได้เฉพาะตัวเลขการใช้ token ชื่อ session/skill และช่วงเวลา
2. **ห้ามอัปโหลด .jsonl ไปที่ไหน** และห้ามส่งเนื้อหางานลูกค้าเข้า API count_tokens
   สคริปต์ส่งเฉพาะไฟล์ที่ผู้ใช้ชี้ให้นับ — ถ้าไฟล์นั้นมีข้อมูลลูกค้า ต้องเตือนก่อนรัน
3. **ใส่หัวไฟล์ทุกครั้งที่ออก .xlsx** — ชื่อ plugin + เวอร์ชัน, วันที่, โมเดลที่ใช้คิดราคา,
   อัตราแลกเปลี่ยน และโหมดนับ (exact / estimate)
4. ถ้าเจอโมเดลที่ไม่มีราคาในตาราง → **เตือนและไม่นับรวม** ห้ามเดาราคา

skill นี้ไม่แตะโฟลเดอร์ลูกค้าและไม่เขียนอะไรเข้า ERP — ต้องระบุใน SKILL.md ว่ากฎ hook
ข้อที่เกี่ยวกับโฟลเดอร์ลูกค้าจึงไม่บังคับใช้ แต่ 4 ข้อข้างบนยังบังคับ

# ข้อกำหนดของสคริปต์

- ทุกสคริปต์เรียกด้วย path เต็มจาก `${CLAUDE_PLUGIN_ROOT}` — เขียนวิธีเรียกไว้ใน SKILL.md
- ทุกสคริปต์พิมพ์ตาราง markdown ออก stdout เพื่อให้แนบในคำตอบได้ทันที
- หัวรายงานของทุกสคริปต์ต้องระบุโหมดนับ token และโมเดลที่ใช้คิดราคา
- `tm_common.py` เป็นที่เดียวที่รู้เรื่องราคาและการนับ token — สคริปต์อื่นเรียกใช้
- ไม่มี dependency นอก stdlib ยกเว้น openpyxl ที่ import เฉพาะตอนออก Excel
- `pricing.json` ต้องมีฟิลด์ `_note` เตือนให้ตรวจราคากับหน้า pricing ทางการก่อนนำไปเสนอลูกค้า
  และฟิลด์ `updated` ระบุวันที่ปรับราคาครั้งล่าสุด

# กฎห้าม

1. **ห้ามให้โมเดลคำนวณราคาเอง** — คิดในสคริปต์เท่านั้น
2. **ห้ามแสดงเนื้อหา transcript** และห้ามส่งข้อมูลลูกค้าออกนอกเครื่อง
3. **ห้ามบอกว่าเป็นเงินที่จ่ายจริง** สำหรับผู้ใช้แพ็กเกจ Pro/Max
4. **ห้ามรายงานตัวเลข estimate โดยไม่บอกว่าเป็น estimate**
5. **ห้ามเดาราคาโมเดลที่ไม่มีในตาราง**
6. ห้าม hardcode อัตราแลกเปลี่ยน — ถ้าผู้ใช้อยากเห็นเป็นบาท ให้ถามอัตราหรือบอกว่าใช้อัตราเท่าไร

# หัวข้อที่ SKILL.md ต้องมี

1. ตารางจับคู่ "คำถามของผู้ใช้ → สคริปต์ที่ใช้"
2. วิธีเรียกสคริปต์ด้วย path เต็ม
3. หนึ่งหัวข้อต่อหนึ่งสคริปต์: ตัวอย่างคำสั่ง + วิธีตีความผลที่ต้องอธิบายให้ผู้ใช้
4. กฎของ plugin ที่ใช้กับ skill นี้ (ข้อความปลอดภัยข้อมูล 4 ข้อ)
5. เรื่องราคาและอัตราแลกเปลี่ยน
6. วิธีรายงานผล — สรุปภาษาไทยสั้น ๆ: ยอดรวม, 3 อันดับที่กินมากสุด, ข้อเสนอแนะที่ลดต้นทุนได้จริง
````
