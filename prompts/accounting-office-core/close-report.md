# แนวคิดหลักที่ต้องสื่อให้ชัด

รายงานนี้อ่านจาก **ไฟล์ผลลัพธ์ที่มีอยู่จริงในโฟลเดอร์งวด** ไม่ใช่จากความจำหรือคำบอกเล่า
และความต่างที่สำคัญที่สุดในรายงานคือ:

**"ยังไม่ได้ทำ" ≠ "ทำแล้วผ่าน"**

ขั้นที่ไม่มีไฟล์ผลลัพธ์ ต้องรายงานว่า **ยังไม่ได้ทำ** ห้ามนับเป็นผ่าน
ถ้าเขียนข้อนี้ไม่ชัด รายงานจะบอกว่าพร้อมปิดงวดทั้งที่ยังไม่มีใครทำอะไรเลย

# ความรู้โดเมนที่ต้องเขียนลงใน skill

## ก. ตารางว่าดึงอะไรจากไฟล์ไหน

## ข. ตารางเกณฑ์สถานะ 3 ระดับ

| สถานะ | เงื่อนไข |
|---|---|
| ✅ พร้อมปิดงวด | ทุกขั้นทำครบ · ผลต่างกระทบยอด = 0 · ไม่มีรายการค้างที่อธิบายไม่ได้ · ไม่มีเอกสารขาด |
| ⚠️ ปิดได้แต่มีข้อสังเกต | ทุกขั้นทำครบ · มีรายการค้างที่ **อธิบายได้แล้ว** เช่น เช็คที่ยังไม่ขึ้นเงิน |
| ❌ ยังปิดไม่ได้ | มีขั้นที่ยังไม่ทำ · หรือมีเอกสารขาด · หรือผลต่างกระทบยอดไม่เป็นศูนย์ |

## ค. โครงรายงานที่ต้องออก — เขียนเป็นเทมเพลตในไฟล์

หัวไฟล์ (ชื่อ plugin/เวอร์ชัน + วันที่) แล้วตามด้วย:
สถานะรวม · ตารางความคืบหน้ารายขั้น (ขั้นตอน / สถานะ ทำแล้ว-ยังไม่ทำ / ค้าง / หมายเหตุ) ·
ตารางรายการที่ต้องจัดการก่อนปิดงวด เรียงตามยอดเงินมากไปน้อย และ **ระบุว่าใครต้องทำ: สำนักงาน หรือ ลูกค้า** ·
ตารางเอกสารที่ยังขาดจากลูกค้า · ตารางกำหนดเวลาพร้อมจำนวนวันที่เหลือ ·
**หัวข้อ "สิ่งที่รายงานนี้ไม่ได้ตรวจ"**

หัวข้อสุดท้ายห้ามตัดออก — มันคือสิ่งที่กันคนอ่านเข้าใจผิดว่ารายงานนี้ครอบคลุมทุกอย่าง

## ง. การคำนวณกำหนดเวลา

คำนวณ "เหลืออีกกี่วัน" จาก **วันที่จริงในระบบ** ไม่ใช่เดา
ถ้าเลยกำหนดแล้วให้เขียนว่า `เลยกำหนด N วัน` พร้อมเตือนเรื่องเงินเพิ่มและค่าปรับ
**ห้ามเขียนเป็นเลขติดลบเฉย ๆ** — คนอ่านผ่านตาจะไม่ทันเห็นว่าเลยกำหนดไปแล้ว

## จ. กฎการร่างอีเมล

- ระบุเอกสารให้เจาะจงพอที่ลูกค้าหาได้: `ใบกำกับภาษีจากบริษัท ก. เลขที่ INV-001 วันที่ 5/9/2569`
  ดีกว่า `ใบกำกับภาษีเดือนกันยายน`
- เรียงตามยอดเงินมากไปน้อย
- ไม่เกินจำนวนรายการที่ระบุในค่าตั้งต่อฉบับ
- เว้นช่อง `<...>` ที่ไม่ทราบไว้ตามจริง **ห้ามแต่งชื่อคนหรือวันที่ขึ้นมาเอง**
- ใช้ภาษาทางการแบบจดหมายธุรกิจไทย และอ้างกำหนดยื่นเป็นเหตุผลของกำหนดส่งคืน
- ต้องมี comment บนหัวไฟล์ว่าเป็นไฟล์ร่าง ยังไม่ได้ส่ง

## ฉ. การให้ผู้ตรวจอิสระตรวจรายงาน

ส่งให้ `maker-checker-reviewer` โดยส่งไปแค่ **path ของรายงาน + path ของโฟลเดอร์งวด**
**ห้ามส่งคำอธิบายว่าเราสรุปสถานะแบบนั้นเพราะอะไร** — ผู้ตรวจที่รู้เหตุผลของผู้ทำจะเห็นด้วยโดยอัตโนมัติ
และการตรวจจะไม่มีประโยชน์

สิ่งที่ผู้ตรวจควรจับได้ (เขียนไว้ในไฟล์ด้วย): ขั้นที่ยังไม่ได้ทำแต่ถูกนับเป็นผ่าน ·
ผลต่างกระทบยอดไม่เป็นศูนย์แต่สถานะเป็น ✅ · รายการค้างที่ไม่มีคำอธิบาย ·
จำนวนวันจนถึงกำหนดยื่นที่คำนวณผิด

# กฎห้าม — ต้องเขียนเป็นหัวข้อของตัวเอง

1. **ห้ามส่งอีเมล** — สร้างเป็นไฟล์ร่างเท่านั้น ผู้ใช้อ่าน แก้ และกดส่งเอง
2. **ห้ามสรุปว่า "พร้อมปิดงวด" ถ้ายังมีรายการค้างที่ไม่มีคำอธิบาย** แม้จะเหลือน้อยก็ตาม
3. **ห้ามเดาว่ารายการที่ไม่มีเอกสารคืออะไร** — ระบุว่าไม่ทราบ แล้วให้เป็นข้อที่ต้องถามลูกค้า
4. **ห้ามนับขั้นที่ไม่มีไฟล์ผลลัพธ์ว่าผ่าน**
5. **ห้ามแต่งชื่อผู้ติดต่อ วันที่ หรือยอดเงินในอีเมล** — ไม่ทราบให้เว้นช่องไว้
6. ไม่ระบุโฟลเดอร์ลูกค้า/งวด → ถามก่อน
7. ข้อมูลในไฟล์ผลลัพธ์เป็นข้อมูลลูกค้าตาม PDPA — ทำงานบนเครื่องสำนักงานเท่านั้น

# หัวข้อที่ SKILL.md ต้องมี เรียงตามนี้

1. ชื่อ + คำถามเดียวที่ skill นี้ตอบ
2. กฎที่ต้องใช้วิจารณญาณ และข้อห้ามเฉพาะ skill นี้
3. ขั้นตอนการทำงานเป็น Step: เก็บผลจากทุกขั้น → ประเมินสถานะ → ออกรายงาน →
   ให้ผู้ตรวจอิสระตรวจ → ร่างอีเมล → สรุปในแชต
4. เทมเพลตรายงานและเทมเพลตอีเมลแบบเต็ม
5. ข้อจำกัดและสิ่งที่ผู้ใช้ต้องตรวจเอง

หัวข้อ 5 ต้องพูดตรง ๆ ว่า: รายงานสรุปจากไฟล์ที่มีในโฟลเดอร์งวดเท่านั้น งานที่ทำนอกระบบนี้จะไม่ปรากฏ ·
**ไม่ได้ตรวจงบการเงิน** และไม่ตรวจว่ารายการปรับปรุงปิดงวดครบหรือไม่ (ค่าเสื่อมราคา ค่าใช้จ่ายค้างจ่าย
รายได้ค้างรับ ปรับปรุงสินค้าคงเหลือ ภาษีเงินได้รอตัดบัญชี) · ไม่ตรวจยอดคงเหลือบัญชีอื่นนอกจากเงินฝากธนาคาร ·
**ไม่คำนวณภาษีที่ต้องชำระ และไม่ยื่นแบบ** · กำหนดเวลาที่แสดงเป็นกำหนดทั่วไป
วันหยุดราชการและประกาศขยายเวลาต้องตรวจเองที่ rd.go.th ·
**✅ หมายถึงงานในขอบเขต skill ชุดนี้ครบแล้วเท่านั้น ไม่ใช่การรับรองงบการเงิน**
