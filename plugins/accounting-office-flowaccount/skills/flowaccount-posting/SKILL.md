# บันทึกค่าใช้จ่ายเข้า FlowAccount

ขั้นสุดท้ายของสายงาน: รายการที่ตรวจแล้ว → เอกสารใน FlowAccount **สถานะรออนุมัติ**

> plugin นี้ต้องใช้คู่กับ `accounting-office-core` — ถ้ายังไม่ได้ติดตั้ง ให้บอกผู้ใช้ก่อน

---

## กฎบังคับ (ทุก skill ในชุดนี้ใช้เหมือนกัน)

1. **ทำงานเฉพาะในโฟลเดอร์ลูกค้าที่ผู้ใช้ระบุ** ห้ามอ่านหรือเขียนโฟลเดอร์ลูกค้ารายอื่น
2. **อ่าน `client-profile.md` ก่อนเริ่มงานทุกครั้ง** ถ้าไม่มี ให้หยุดแล้วบอกผู้ใช้ให้รัน `/new-client` ก่อน
3. **ก่อน action ที่เขียนข้อมูลเข้า ERP** ต้องแสดงชื่อบริษัทและเลขผู้เสียภาษีของบริษัทปลายทางใน ERP แล้วเทียบกับ `client-profile.md` — ถ้าไม่ตรง **หยุดทันที**
4. **สร้างเอกสารใน ERP เป็นสถานะรออนุมัติเท่านั้น** ห้ามอนุมัติ ห้ามบันทึกรับชำระ ห้าม void ห้ามลบ
5. **ใส่ชื่อ plugin และเลขเวอร์ชันไว้ในหัวทุกไฟล์ที่สร้าง** เช่น `accounting-office-flowaccount v1.0.0 — 2569-09-16`

---

## หลักการที่ห้ามละเมิดเพิ่มเติม (เฉพาะงานเขียนเข้า ERP)

1. **ห้ามสร้างเอกสารโดยไม่ผ่านการอนุมัติของผู้ใช้** — ต้อง preview ให้ดูทั้งกองก่อนเสมอ
2. **ห้ามสร้าง vendor ใหม่ก่อนค้นหาให้ครบทุกวิธี** — เคยเกิด vendor ซ้ำจากการข้ามขั้นนี้
3. **ห้ามบันทึกทับเอกสารที่มีอยู่แล้ว** — ตรวจซ้ำทุกใบ
4. **ห้ามเดาหมวดหมู่แล้วบันทึกเลย** ถ้าความมั่นใจต่ำกว่า 80% → ถามผู้ใช้
5. **ถ้าไม่มีอะไรต้องบันทึก ให้บอกตรงๆ** อย่าสร้างงานปลอมขึ้นมา
6. **ถ้า response ช้าหรือหลุด ห้ามยิงซ้ำ** — ให้ตรวจสถานะการสร้างเอกสารก่อน

---

## ขอบเขต

**รองรับ** — เอกสารฝั่งซื้อ/ค่าใช้จ่าย ที่ผ่าน `/review-ocr` หรือ `/vouch-expense` แล้ว

**ไม่รองรับ**
- เอกสารฝั่งขาย (ใบแจ้งหนี้ ใบเสร็จรับเงิน ใบกำกับภาษีขาย)
- การอนุมัติเอกสาร บันทึกรับ/จ่ายชำระ void หรือลบเอกสาร
- การแนบไฟล์เอกสารต้นฉบับเข้ากับเอกสารใน FlowAccount (ดูหัวข้อ "ข้อจำกัดเรื่องไฟล์แนบ")
- การแก้ไขผังบัญชีหรือสร้างหมวดหมู่ใหม่

---

## ขั้นตอนการทำงาน

### Step 0 — สำรวจ tool ที่มีจริง

**ก่อนเรียก tool ใดๆ ให้ดูรายชื่อ tool ของ MCP server `flowaccount` ที่โหลดอยู่จริงในเซสชันนี้ก่อน**
ชื่อ tool ที่อ้างถึงในเอกสารนี้เป็นชื่อที่พบในเวอร์ชันที่ทดสอบไว้ — ถ้าไม่ตรง ให้ใช้ชื่อที่มีจริง
และ **อย่าเดาชื่อ tool** ถ้าหา tool ที่ทำงานนั้นไม่เจอ ให้หยุดแล้วแจ้งผู้ใช้

ถ้ายังไม่ได้เชื่อมต่อ/ยังไม่ได้ authorize MCP server ให้แจ้งผู้ใช้ให้ทำก่อน — **ทำแทนไม่ได้**

### Step 1 — โหลดบริบทและตรวจบริษัทปลายทาง

1. อ่าน `client-profile.md` และ `mapping-overrides.md`
2. ยืนยันว่า `ERP ที่ใช้` = FlowAccount ถ้าไม่ใช่ → **หยุด**
3. โหลดข้อมูลบริษัทจาก FlowAccount (เช่น `company_settings__load`)
4. **แสดงให้ผู้ใช้เห็นชัดๆ แล้วเทียบ:**

```
บริษัทปลายทางใน FlowAccount : <ชื่อ>  เลขผู้เสียภาษี <13 หลัก>
ตาม client-profile.md        : <ชื่อ>  เลขผู้เสียภาษี <13 หลัก>
ผล: ตรงกัน / ไม่ตรงกัน
```

**ไม่ตรง → หยุดทันที** อย่าบันทึกแม้แต่ใบเดียว การบันทึกผิดบริษัทแก้ยากกว่าการรอ

5. ตรวจสิทธิ์การสร้างเอกสารค่าใช้จ่ายในบัญชีที่เชื่อมต่ออยู่ ถ้าไม่มีสิทธิ์ → หยุด แจ้งผู้ใช้
6. โหลดหมวดหมู่ค่าใช้จ่ายสด (`expense__list_business_categories`)
   → **ใช้ค่าที่ดึงสดเสมอ** `references/expense-category-mapping.md` เป็นแค่กฎการเลือกและ snapshot อ้างอิง

### Step 2 — เตรียมรายการที่จะบันทึก

รับ input จากไฟล์ผล vouch/OCR ของงวดนั้น แล้ว**คัดเฉพาะแถวที่ผ่าน**
รายการที่ยังติดสถานะ `ไม่พบเอกสาร` / `ต้องแก้` → **ไม่บันทึก** แล้วรายงานแยกว่าข้ามไปกี่ใบเพราะอะไร

ฟิลด์ที่ต้องมีครบต่อ 1 ใบ → ดู `references/expense-category-mapping.md` หัวข้อ "ฟิลด์ที่ต้องส่ง"

ตรวจคณิตศาสตร์ทุกใบก่อนไปต่อ:
```
|ยอดก่อน VAT × 0.07 − VAT| ≤ 0.02
ยอดก่อน VAT + VAT = ยอดรวม
```
ไม่ตรง → **ไม่บันทึกใบนั้น** แจ้งผู้ใช้ให้ตรวจเอกสาร

### Step 3 — กันเอกสารซ้ำ (ทำก่อนเสมอ)

ค้นเอกสารที่มีอยู่แล้วใน FlowAccount ด้วย **เลขที่เอกสารของผู้ขาย** ก่อน
ถ้าไม่เจอ ให้ค้นซ้ำด้วยชื่อ vendor + ยอดรวม

**ถือว่าซ้ำเมื่อตรงกันครบ 3 อย่าง**: เลขที่เอกสารผู้ขาย (`reference`) + ยอดรวม + วันที่เอกสาร
→ ข้ามใบนั้น แล้วรายงานว่า "ซ้ำ — บันทึกไว้แล้วที่ `<เลขที่เอกสารในระบบ>`"

### Step 4 — กัน vendor ซ้ำ

ค้นตามลำดับนี้ **ห้ามข้ามขั้น**:
1. ค้นด้วย **เลขผู้เสียภาษี 13 หลัก** (แม่นที่สุด)
2. ค้นด้วย **คำสั้นๆ ในชื่อ** (เช่น `เอิร์ธ` ไม่ใช่ `บริษัท เอิร์ธซาวนด์ จำกัด`) — เป็น partial match
3. ค้นด้วยชื่อภาษาอังกฤษ ถ้ามี

| ผลลัพธ์ | ทำอย่างไร |
|---|---|
| เจอ 1 ราย | ใช้ `contact_id` ของรายนั้น **ห้ามส่งชื่อ vendor คู่กัน** |
| เจอหลายราย | เลือกรายที่มีเลขผู้เสียภาษีและที่อยู่ครบ แล้ว**แจ้งผู้ใช้ว่ามีซ้ำ** ควรไปรวมในระบบ |
| ไม่เจอ | ทำเครื่องหมาย "vendor ใหม่" ในตาราง preview ให้ผู้ใช้เห็นก่อน |

> FlowAccount MCP **ไม่มี tool สร้าง contact แยกต่างหาก** — vendor ใหม่จะถูกสร้างอัตโนมัติ
> ตอนสร้างเอกสารเมื่อส่งชื่อ vendor ที่ยังไม่มีในระบบ นี่คือเหตุผลที่ต้องค้นให้ครบก่อน

**ที่อยู่ในเอกสารต่างจากที่อยู่ในระบบ ไม่ใช่เหตุผลให้สร้าง vendor ใหม่** — ใช้รายเดิม แล้วแจ้งผู้ใช้

### Step 5 — จับคู่หมวดหมู่

ใช้กฎใน `references/expense-category-mapping.md`
ลำดับความสำคัญ: `mapping-overrides.md` ของลูกค้า **ชนะ** กฎ default เสมอ

ความมั่นใจ < 80% → ใส่ ⚠️ ในตาราง preview พร้อมเสนอตัวเลือกสำรอง 2 ตัวให้ผู้ใช้เลือก

### Step 6 — Preview (บังคับ)

ใช้ tool ตรวจสอบ/คำนวณแบบไม่เขียนจริง (เช่น `expense__validate_expense`
หรือสร้างโดยตั้ง `confirm=false`) แล้วแสดง **ทั้งกองพร้อมกัน**:

| # | ไฟล์ | ผู้ขาย | เลขที่ | วันที่ | หมวดหมู่ | ก่อน VAT | VAT | WHT | รวม | สถานะ |
|---|---|---|---|---|---|---|---|---|---|---|

ตามด้วยยอดรวมทั้งกอง และ **ต้องถามผู้ใช้ 2 ข้อนี้เสมอ ไม่มีค่า default**:
- VAT/ส่วนลด เป็นแบบ **แยกรายบรรทัด (inline)** หรือ **ท้ายเอกสาร (document level)**
- ราคาในเอกสาร **รวม VAT แล้ว** หรือ **ยังไม่รวม**

รอคำยืนยันจากผู้ใช้ **ห้ามข้ามไป Step 7 เอง**

### Step 7 — บันทึกจริง

สร้างเอกสารทีละใบ (`confirm=true`) แล้วเก็บ `record_id`, เลขที่เอกสารในระบบ
และค่า idempotency key **ที่ response คืนกลับมา**

**ถ้า response ช้า หลุด หรือ timeout → ห้ามยิงซ้ำ**
ให้ตรวจสถานะการสร้างเอกสารด้วย key ที่ระบบคืนมา (เช่น `documents__get_creation_status`)
รหัสสถานะและความหมาย → `references/status-codes.md`

### Step 8 — ไฟล์แนบ (ข้อจำกัดที่ต้องบอกผู้ใช้ทุกครั้ง)

> ⚠️ **FlowAccount MCP ไม่มี tool อัปโหลดไฟล์แนบเข้าเอกสารค่าใช้จ่าย**
> เอกสารที่สร้างจะไม่มีไฟล์แนบ

ทางออกที่ทำได้จริง:
1. **แนะนำ** — ใส่ path หรือลิงก์ของไฟล์ต้นฉบับลงในหมายเหตุภายใน (`internal_notes`)
   เช่น `เอกสารต้นฉบับ: ลูกค้า/<ชื่อ>/<งวด>/source-docs/INV-001.pdf`
   ตามรอยกลับได้ และไม่พิมพ์ออกหน้าเอกสาร
2. ผู้ใช้เปิดเอกสารใน FlowAccount แล้วแนบไฟล์เอง

**ต้องแจ้งผู้ใช้ทุกครั้งว่าไฟล์ยังไม่ได้แนบ** อย่าปล่อยให้เข้าใจผิดว่าแนบแล้ว

### Step 9 — สรุปและบันทึกผล

บันทึกที่ `<งวด>/output/post-flowaccount-<งวด>.md`
หัวไฟล์: `<!-- accounting-office-flowaccount v1.0.0 | <ลูกค้า> | <งวด> | <วันที่> -->`

| # | ไฟล์ต้นฉบับ | ผลลัพธ์ | เลขที่เอกสารในระบบ | หมายเหตุ |
|---|---|---|---|---|

สรุปในแชต: บันทึกใหม่ N ใบ / ข้ามเพราะซ้ำ M ใบ / ข้ามเพราะยังตรวจไม่ผ่าน K ใบ / ผิดพลาด J ใบ
และรายการที่ต้องให้คนตามต่อ: **vendor ใหม่ที่ถูกสร้าง · หมวดหมู่ที่ไม่มั่นใจ · ไฟล์ที่ยังไม่แนบ ·
เอกสารทั้งหมดยังอยู่ในสถานะรออนุมัติ**

## ภาษีหัก ณ ที่จ่าย

**ดูจากเอกสารว่าหักจริงหรือไม่ อย่าคำนวณเพิ่มเอง**

- ยอดที่จ่ายจริง = ยอดรวมทั้งสิ้น → **ไม่ได้หัก** อย่าใส่ WHT
- ยอดที่จ่ายจริง < ยอดรวม → หักแล้ว ใส่อัตราตามเอกสาร

ถ้าเอกสารเข้าข่ายต้องหักแต่ไม่ได้หัก → **แจ้งเตือนผู้ใช้ว่าอาจมีประเด็นภาษี**
แต่ยังบันทึกตามความจริงที่เกิดขึ้น อัตราอ้างอิงอยู่ใน
`accounting-office-core` → `skills/wht-prep/references/wht-rates.md`

## ข้อจำกัดและสิ่งที่ผู้ใช้ต้องตรวจเอง

- **เอกสารที่สร้างอยู่ในสถานะรออนุมัติ** ผู้ใช้ต้องตรวจและอนุมัติเองใน FlowAccount
- **ไฟล์เอกสารต้นฉบับไม่ถูกแนบ** — ต้องแนบเองถ้าต้องการ
- หมวดหมู่ที่จับคู่ให้เป็นการอนุมานจากเนื้อหาเอกสาร — **ผู้ทำบัญชีต้องตรวจทุกใบ**
  โดยเฉพาะเส้นแบ่งระหว่าง ต้นทุน / ค่าใช้จ่าย / ทรัพย์สิน ซึ่งกระทบทั้งงบและภาษี
- ไม่ตัดสินว่ารายจ่ายเป็นรายจ่ายต้องห้ามตามมาตรา 65 ตรี และไม่ตัดสินสิทธิขอคืนภาษีซื้อ
- การกันเอกสารซ้ำอาศัยเลขที่เอกสารของผู้ขาย — **ถ้าเอกสารไม่มีเลขที่ หรือ OCR อ่านเลขที่ผิด
  การกันซ้ำจะไม่ทำงาน** ต้องตรวจเองก่อนอนุมัติ
- ยอดคงเหลือและรายงานภาษีใน FlowAccount ต้องกระทบยอดเองอีกชั้น
- ข้อมูลถูกส่งออกไปยังระบบ FlowAccount ผ่าน MCP — ผู้ใช้รับผิดชอบการขอความยินยอมตาม PDPA
  และการจัดการสิทธิ์เข้าถึงบัญชีลูกค้า
