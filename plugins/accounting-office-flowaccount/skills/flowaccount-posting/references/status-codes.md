# สถานะเอกสารและรหัสข้อผิดพลาด — FlowAccount MCP

> รหัสเหล่านี้มาจากเวอร์ชันที่ทดสอบไว้ ณ วันที่จัดทำ
> **ถ้าเจอรหัสที่ไม่มีในตาราง ห้ามเดาความหมาย** — ให้แสดงข้อความดิบที่ระบบคืนมาให้ผู้ใช้เห็น แล้วหยุด

---

## สถานะเอกสารหลังสร้าง

| สถานะ | ความหมาย | ต้องทำอะไรต่อ |
|---|---|---|
| `awaiting` | **รออนุมัติ** | ถูกต้องแล้ว — ผู้ใช้ต้องไปตรวจและอนุมัติเองใน FlowAccount |
| `approved` | อนุมัติแล้ว | **skill นี้ต้องไม่ทำให้เกิดสถานะนี้** ถ้าเจอ แปลว่ามีคนอนุมัติจากที่อื่น |
| `void` | ยกเลิกแล้ว | skill นี้ไม่ยกเลิกเอกสาร — ถ้าเจอ ให้รายงานอย่างเดียว |

ช่อง `saleAndPurchaseChannel` จะเป็น `"MCP"` ใช้ระบุได้ว่าเอกสารมาจากช่องทางนี้
มีประโยชน์ตอนตรวจสอบย้อนหลังว่ารายการไหนที่ระบบสร้าง

---

## รหัสข้อผิดพลาดที่พบบ่อย

| รหัส / อาการ | สาเหตุ | ต้องทำอะไร |
|---|---|---|
| `permission_denied` | บัญชีที่เชื่อมต่อไม่มีสิทธิ์สร้างเอกสารค่าใช้จ่าย | **หยุด** แจ้งผู้ใช้ให้เปิดสิทธิ์ — ทำแทนไม่ได้ |
| `duplicate_in_flight` | คำขอเดิมกำลังประมวลผลอยู่ | **ห้ามยิงซ้ำ** ให้ตรวจสถานะด้วย key ที่ response คืนมา |
| `cached_replay` | เคยส่งคำขอนี้แล้ว ระบบคืนผลเดิม | **ปลอดภัย ไม่ได้สร้างซ้ำ** บันทึกผลเดิมแล้วไปใบถัดไป |
| `upstream_unavailable` | ระบบกันซ้ำของ FlowAccount ไม่ตอบ | รอแล้วลองใหม่ **อย่าวนยิงรัว** และอย่าปิดการกันซ้ำ |
| `validation_error` | ข้อมูลไม่ครบ/ผิดรูปแบบ | อ่านฟิลด์ที่ระบบบอก แก้ที่ต้นทาง **ห้ามเติมค่ามั่วให้ผ่าน** |
| `contact_not_found` | `contact_id` ที่ส่งไปไม่มีในระบบ | ค้น vendor ใหม่ตามลำดับใน SKILL.md Step 4 |
| `category_required` / warning เรื่อง map บรรทัด | ไม่ได้ส่ง `category_id` | **ห้ามบันทึกทั้งที่ยัง warning** — กลับไปจับคู่หมวดหมู่ |
| timeout / ไม่มี response | เครือข่ายหรือระบบช้า | **ห้ามยิงซ้ำ** ตรวจสถานะก่อนเสมอ |

---

## หลักปฏิบัติเมื่อเกิดข้อผิดพลาด

1. **ไม่มีคำตอบ ≠ ไม่ได้สร้าง** — เอกสารอาจถูกสร้างแล้วแต่ response หาย
   ตรวจสถานะก่อนตัดสินใจทุกครั้ง
2. **หยุดทั้งกองเมื่อเจอ `permission_denied` หรือบริษัทปลายทางไม่ตรง** — ไม่ใช่ข้ามใบแล้วทำต่อ
3. **ทำต่อได้เมื่อเป็นปัญหาเฉพาะใบ** (`validation_error`, `contact_not_found`)
   แต่ต้องรวบรวมทุกใบที่ข้ามไว้รายงานตอนท้าย
4. **ห้ามปิดหรือข้ามกลไกกันซ้ำเพื่อให้งานเดินต่อ**
5. รายงานผลตามจริง — ถ้าไม่แน่ใจว่าใบไหนถูกสร้างหรือไม่
   ให้บอกผู้ใช้ตรงๆ ว่าต้องเข้าไปตรวจใน FlowAccount เอง **อย่าเดาว่าสำเร็จ**

## ตรวจซ้ำหลังบันทึกเสร็จทั้งกอง

ก่อนสรุปให้ผู้ใช้ ให้ค้นรายการเอกสารค่าใช้จ่ายในช่วงวันที่ของงวดนั้นอีกครั้ง
แล้วเทียบกับรายการที่ตั้งใจจะบันทึก:

- จำนวนเอกสารที่เพิ่มขึ้น = จำนวนที่รายงานว่าสร้างสำเร็จหรือไม่
- มีเอกสารที่เลขที่อ้างอิงซ้ำกันหรือไม่
- ยอดรวมตรงกับที่ preview ไว้หรือไม่

ถ้าไม่ตรง → **รายงานความไม่ตรงนั้นตามจริง** พร้อมรายการที่ต้องให้คนเข้าไปตรวจ
