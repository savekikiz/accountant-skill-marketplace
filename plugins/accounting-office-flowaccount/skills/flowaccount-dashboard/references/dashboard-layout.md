# สัญญาของ data pack และหน้าตาไฟล์ Dashboard

ไฟล์นี้คือข้อตกลงระหว่าง **skill (คนดึงข้อมูล)** กับ **`scripts/build_dashboard.py` (คนวาดไฟล์)**
สคริปต์ไม่รู้จัก ERP เลย มันรู้แค่รูปของ JSON ในไฟล์นี้

> สำเนาไฟล์นี้ต้องตรงกันทั้ง 2 plugin ของ ERP — ดู `scripts/sync_hooks_lib.py`

---

## 1. โครง JSON

```json
{
  "meta": {
    "erp": "<FlowAccount หรือ PEAK>",
    "client": "บริษัท ตัวอย่างเทรดดิ้ง จำกัด",
    "company_in_erp": "บริษัท ตัวอย่างเทรดดิ้ง จำกัด (0105560000000)",
    "period_label": "2569-09",
    "compare_label": "2569-08",
    "fetched_at": "2569-09-18 14:05",
    "notes": ["ยอดขายรวมเอกสารสถานะรออนุมัติ 3 ใบ", "ยังไม่ได้กระทบยอดธนาคารงวดนี้"]
  },
  "kpis":   [ /* การ์ดตัวเลขสำคัญบนชีตแดชบอร์ด */ ],
  "checks": [ /* การตรวจยอดข้ามแหล่ง */ ],
  "blocks": [ /* ตารางแต่ละชีต */ ],
  "charts": [ /* กราฟบนชีตแดชบอร์ด */ ]
}
```

`meta.notes` คือที่สำหรับข้อสังเกตที่ตัวเลขบอกไม่ได้ — ใส่ให้ครบ
ผู้อ่านรายงานไม่ได้อยู่ในห้องตอนที่คุณดึงข้อมูล

---

## 2. `kpis` — การ์ดตัวเลขสำคัญ

```json
{
  "name": "รายได้รวม",
  "value": 1250000.0,
  "compare": 1100000.0,
  "higher_is_better": true,
  "status": "ok",
  "source": {"tool": "accounting__get_profit_loss",
             "params": {"period": "2026-09"},
             "fetched_at": "2569-09-18 14:01"}
}
```

- `higher_is_better: false` สำหรับตัวเลขที่เพิ่มขึ้นแล้วแย่ (ค่าใช้จ่าย ลูกหนี้คงค้าง)
  สคริปต์ใช้ค่านี้เลือกสีของช่อง % เปลี่ยนแปลง — ไม่ใส่จะถือว่า `true`
- ดึงไม่ได้ → `"status": "unavailable"` + `"reason": "<เหตุผลตามจริง>"` **แล้วไม่ต้องใส่ `value`**
  สคริปต์จะเขียนว่า `ดึงไม่ได้` พร้อมพื้นสีเทา **ห้ามใส่ 0 เพื่อให้การ์ดดูครบ**
- % เปลี่ยนแปลงสคริปต์คำนวณให้จาก `value` กับ `compare` — ไม่ต้องส่งมา

**ชุด KPI มาตรฐาน 6 ตัว:** รายได้รวม · ค่าใช้จ่ายรวม · กำไรสุทธิ · ลูกหนี้คงค้าง ·
เจ้าหนี้คงค้าง · เงินสดและเงินฝาก

## 3. `blocks` — หนึ่งบล็อกหนึ่งตาราง

```json
{
  "id": "ar_aging",
  "sheet": "อายุลูกหนี้",
  "title": "อายุลูกหนี้คงค้าง ณ 2569-09-30",
  "status": "ok",
  "total_row": true,
  "source": {"tool": "accounting__get_ar_aging",
             "params": {"as_of": "2026-09-30"},
             "fetched_at": "2569-09-18 14:03"},
  "columns": [
    {"key": "bucket", "label": "ช่วงอายุ", "type": "text"},
    {"key": "amount", "label": "จำนวนเงิน", "type": "money"},
    {"key": "count",  "label": "จำนวนใบ",  "type": "int"}
  ],
  "rows": [
    {"bucket": "ยังไม่ครบกำหนด", "amount": 210000.0, "count": 12},
    {"bucket": "เกิน 90 วัน",     "amount": 15000.0,  "count": 1}
  ]
}
```

| ฟิลด์ | ความหมาย |
|---|---|
| `id` | ชื่อที่ `charts` และชีตที่มาของข้อมูลใช้อ้าง — ต้องไม่ซ้ำ |
| `sheet` | ชื่อชีต (ยาวไม่เกิน 31 ตัวอักษรตามข้อจำกัดของ Excel) หลายบล็อกใช้ชีตเดียวกันได้ |
| `status` | `ok` / `partial` / `unavailable` |
| `reason` | บังคับเมื่อ `status` ไม่ใช่ `ok` |
| `total_row` | `true` = ให้สคริปต์ใส่แถวรวมเป็นสูตร `SUM()` (สูตรจริง ไม่ใช่ค่าคงที่) |
| `columns[].type` | `text` / `money` / `int` / `pct` |
| `columns[].total` | `false` = ไม่ต้องรวมคอลัมน์นี้ในแถวรวม (เช่น คอลัมน์อัตราส่วน) |
| `columns[].width` | ความกว้างคอลัมน์ ถ้าต้องการกำหนดเอง |

- ค่า `pct` ส่งเป็นทศนิยม (`0.136` = 13.6%) สคริปต์จะระบายเขียว/แดงตามเครื่องหมายให้
- ช่องที่ไม่มีค่าใน `rows` สคริปต์เขียน `ดึงไม่ได้` พร้อมพื้นสีเทา **ไม่ใช่ 0**
- `status: "unavailable"` → สคริปต์เขียนแถวเดียวว่าดึงไม่ได้พร้อมเหตุผล แล้วไม่วาดกราฟของบล็อกนั้น

**ชุดชีตมาตรฐาน 10 ชีต:** แดชบอร์ด · งบกำไรขาดทุน · งบแสดงฐานะการเงิน · งบทดลอง ·
อายุลูกหนี้ · อายุเจ้าหนี้ · ยอดขาย · ค่าใช้จ่าย · เงินรับ-จ่าย · ที่มาของข้อมูล
(ชีตแดชบอร์ดกับที่มาของข้อมูล สคริปต์สร้างให้เอง)

## 4. `checks` — การตรวจยอดข้ามแหล่ง

```json
{"name": "รายได้ใน P&L = ยอดรวมสมุดรายวันขาย",
 "left": 1250000.0, "right": 1250000.0, "tolerance": 1.0}
```

- `tolerance` ไม่ใส่ = 1.00 บาท
- ฝั่งใดดึงไม่ได้ → ส่ง `null` สคริปต์จะเขียนว่า `ตรวจไม่ได้` ไม่ใช่ `ผ่าน`
- **ไม่ผ่านไม่ใช่ความล้มเหลวของ skill** — มันคือข้อมูล ห้ามปรับตัวเลขให้ตรงกัน
  สคริปต์พิมพ์รายการที่ไม่ผ่านออก stdout เพื่อให้ยกไปใส่สรุปในแชต

## 5. `charts` — กราฟบนชีตแดชบอร์ด

```json
{"type": "bar", "block": "ar_aging", "cat": "bucket",
 "values": ["amount"], "title": "อายุลูกหนี้", "anchor": "H4"}
```

| ฟิลด์ | ความหมาย |
|---|---|
| `type` | `bar` / `line` / `pie` |
| `block` | `id` ของบล็อกที่เป็นแหล่งข้อมูล |
| `cat` | `key` ของคอลัมน์ที่ใช้เป็นแกนหมวด |
| `values` | รายชื่อ `key` ของคอลัมน์ตัวเลขที่จะพลอต (หลายตัวได้) |
| `anchor` | เซลล์มุมซ้ายบนของกราฟบนชีตแดชบอร์ด เช่น `H4`, `H20`, `P4` |

กราฟอ้าง **เซลล์จริงในชีตของบล็อกนั้น** (cross-sheet reference) ไม่ได้ก็อปค่ามาแปะ
เปิดใน Excel แล้วแก้ตัวเลขในตาราง กราฟจะขยับตาม — นี่คือเหตุผลที่ต้องเป็นไฟล์ Excel
ไม่ใช่รูปภาพ

**ชุดกราฟมาตรฐาน 4 รูป:** รายได้-ค่าใช้จ่ายเทียบงวดก่อน (bar) · อายุลูกหนี้ (bar) ·
สัดส่วนค่าใช้จ่ายตามหมวดหมู่ (pie) · เงินรับ-จ่ายตามช่องทาง (bar)
บล็อกไหนดึงไม่ได้ กราฟนั้นจะถูกข้ามพร้อมรายงานว่าข้ามเพราะอะไร

## 6. สิ่งที่สคริปต์ทำให้เอง — ไม่ต้องส่งมาใน JSON

- หัวไฟล์ `<ชื่อ plugin> v<เวอร์ชัน> | ลูกค้า | กิจการใน ERP | งวด | งวดเทียบ | ดึงเมื่อ`
  (อ่านเวอร์ชันจาก `plugin.json` — **ห้าม hardcode**)
- บรรทัดอธิบายว่า `ดึงไม่ได้` ไม่ใช่ศูนย์
- ชีต **ที่มาของข้อมูล** — ทุกบล็อกและทุก KPI พร้อม tool, พารามิเตอร์, จำนวนแถว, สถานะ, เวลาที่ดึง
- % เปลี่ยนแปลงของ KPI, แถวรวมแบบสูตร, สีตามสถานะ, การตรึงหัวตาราง, รูปแบบตัวเลข

## 7. ตรวจไฟล์ที่ได้ก่อนส่งผู้ใช้

- [ ] หัวไฟล์มีชื่อ plugin + เวอร์ชัน (ไม่มี → hook จะเตือนหลังเขียน)
- [ ] ทุกบล็อกที่ `unavailable` ปรากฏในสรุปในแชตด้วย ไม่ใช่เฉพาะในไฟล์
- [ ] ไม่มีช่องไหนเป็น 0 ทั้งที่ความจริงคือดึงไม่ได้
- [ ] การตรวจยอดที่ไม่ผ่าน ถูกอธิบายสาเหตุที่เป็นไปได้ไว้ในสรุป
- [ ] ชีตที่มาของข้อมูลมีพารามิเตอร์งวดที่ส่งจริง และเป็น ค.ศ. ตรงกับงวดที่ผู้ใช้ขอ
