# Dashboard จาก FlowAccount → Excel

ดึงตัวเลขที่ FlowAccount รายงาน แล้วจัดเป็นไฟล์เดียวที่ผู้บริหารอ่านรู้เรื่อง
**อ่านอย่างเดียว ไม่เขียนอะไรกลับเข้า ERP เลย**

> plugin นี้ต้องใช้คู่กับ `accounting-office-core` — ถ้ายังไม่ได้ติดตั้ง ให้บอกผู้ใช้ก่อน

---

## กฎบังคับ

กฎ 🔒 บังคับด้วย hook ของ plugin — ทำผิดแล้ว tool call จะถูกปฏิเสธ ไม่ใช่แค่คำเตือน

| กฎ | บังคับโดย |
|---|---|
| ทำงานได้ทีละลูกค้า — โฟลเดอร์รายอื่นถูกบล็อกทั้ง session | 🔒 hook |
| ต้องอ่าน `client-profile.md` ก่อน จึงจะแตะโฟลเดอร์ลูกค้าได้ | 🔒 hook |
| เขียนได้เฉพาะ `<งวด>/output/` — `ocr-output/` `source-docs/` `bank/` อ่านอย่างเดียว | 🔒 hook |
| tool ของ FlowAccount ที่เป็นการอนุมัติ / ยกเลิก / ลบ / จ่ายชำระ / ส่งอีเมล / สร้างลิงก์แชร์ ถูก deny | 🔒 hook |
| ขณะทำงานลูกค้า ห้ามต่อเน็ต/ใช้ MCP ที่ไม่ใช่ ERP/ส่งอีเมล (PDPA) | 🔒 hook |
| ไฟล์ `.xlsx` ต้องมีหัวระบุ plugin + เวอร์ชัน | 🔒 hook (เตือนหลังเขียน — สคริปต์ใส่ให้เองแล้ว) |

ที่เหลือเป็นเรื่องที่ต้องใช้วิจารณญาณ — hook ตรวจแทนไม่ได้:

- **ห้ามเดาตัวเลข** ดึงไม่ได้ให้บันทึกว่าดึงไม่ได้ **ห้ามใส่ 0 แทน**
  ศูนย์ที่ไม่ใช่ศูนย์จริงคือความผิดพลาดที่แพงที่สุดของรายงานผู้บริหาร
- **ห้ามคำนวณตัวเลขที่ ERP รายงานมาแล้วใหม่เอง** — ใช้ค่าที่ระบบให้ ถ้าจะคำนวณเพิ่ม (อัตราส่วน %)
  ต้องกำกับไว้ว่าเป็นค่าที่คำนวณต่อ ไม่ใช่ค่าจากระบบ
- **ถ้าไม่ระบุโฟลเดอร์ลูกค้า/งวด ให้ถามก่อน** อย่าเดา อย่าไล่สแกนทั้งเครื่อง

## ขอบเขต

**รองรับ**
- ดึงข้อมูลด้วย tool อ่านของ FlowAccount MCP (`list_*` / `get_*` / `search_*`)
- Dashboard 1 กิจการ 1 งวด เทียบกับ 1 งวดก่อนหน้า
- ชีตมาตรฐาน: แดชบอร์ด · งบกำไรขาดทุน · งบแสดงฐานะการเงิน · งบทดลอง · อายุลูกหนี้ ·
  อายุเจ้าหนี้ · ยอดขาย · ค่าใช้จ่าย · เงินรับ-จ่าย · ที่มาของข้อมูล
- กราฟในไฟล์ (แท่ง / เส้น / วงกลม) ที่อ้างเซลล์จริง เปิดใน Excel แล้วแก้ข้อมูลกราฟขยับตาม

**ไม่รองรับ**
- เขียน แก้ อนุมัติ หรือลบอะไรใน FlowAccount (ใช้ `/post-expense-flowaccount` สำหรับการบันทึก)
- รวมหลายกิจการไว้ในไฟล์เดียว — **ทำทีละกิจการ**
- แปลงสกุลเงินและงบรวมกิจการ
- พยากรณ์ ประมาณการ หรือคำแนะนำทางธุรกิจ — skill นี้รายงานสิ่งที่เกิดขึ้นแล้ว
- ตัวเลขทางภาษีที่ต้องยื่น (ภ.พ.30 ภ.ง.ด.) — ใช้ skill ของงานนั้นโดยเฉพาะ

## ขั้นตอนการทำงาน

### Step 0 — สำรวจ tool ที่มีจริง

**ก่อนเรียก tool ใดๆ ให้ดูรายชื่อ tool ของ MCP server `flowaccount` ที่โหลดอยู่จริงในเซสชันนี้ก่อน**
ชื่อ tool ใน `references/data-sources.md` เป็นชื่อที่พบในเวอร์ชันที่ทดสอบไว้ — ถ้าไม่ตรง ให้ใช้ชื่อที่มีจริง
และ **อย่าเดาชื่อ tool** ถ้าหา tool ของบล็อกไหนไม่เจอ ให้ทำบล็อกนั้นเป็น `unavailable`
พร้อมเหตุผล **ไม่ใช่ข้ามไปเงียบๆ**

ชื่อ server โผล่ได้สองแบบ: `mcp__flowaccount__…` (จาก `.mcp.json` ของ plugin) และ
`mcp__claude_ai_FlowAccount_MCP__…` (จาก connector ของ claude.ai)

ถ้ายังไม่ได้เชื่อมต่อ/authorize MCP server ให้แจ้งผู้ใช้ทำก่อน — **ทำแทนไม่ได้**

### Step 1 — โหลดบริบทและยืนยันกิจการปลายทาง

1. อ่าน `client-profile.md` และ `mapping-overrides.md`
2. ยืนยันว่า `ERP ที่ใช้` = FlowAccount ถ้าไม่ใช่ → **หยุด**
3. โหลดข้อมูลบริษัทจาก FlowAccount (`company_settings__load`) แล้วแสดงเทียบให้ผู้ใช้เห็น:

```
กิจการใน FlowAccount  : <ชื่อ>  เลขผู้เสียภาษี <13 หลัก>
ตาม client-profile.md : <ชื่อ>  เลขผู้เสียภาษี <13 หลัก>
ผล: ตรงกัน / ไม่ตรงกัน
```

**ไม่ตรง → หยุดทันที** รายงานที่ดึงมาจากกิจการผิดรายอ่านดูสมเหตุสมผลทุกบรรทัด
และไม่มีใครจับได้จนกว่าจะเอาไปใช้ตัดสินใจ

4. ยืนยัน **งวดและงวดเทียบ** กับผู้ใช้ก่อนดึง — พร้อมรูปแบบพารามิเตอร์ที่จะส่งจริง
   (เช่น งวด 2569-09 → `period="2026-09"`) ดูตารางแปลงงวดใน `references/data-sources.md`
   ปี พ.ศ./ค.ศ. สลับกันคือวิธีที่ง่ายที่สุดที่จะได้รายงานของเดือนที่ไม่ได้ขอ

### Step 2 — ตกลงขอบเขตชีตกับผู้ใช้

แสดงรายการบล็อกที่จะดึง (ตาราง "บล็อก → tool" ใน `references/data-sources.md`)
แล้วถามว่าจะเอาครบหรือตัดบางบล็อกออก — **การดึงทุกบล็อกกินเวลาและ token จริง**
ถ้าผู้ใช้ไม่ระบุ ให้ใช้ชุดมาตรฐาน 10 ชีตแล้วบอกว่าใช้ชุดมาตรฐาน

### Step 3 — ดึงข้อมูลลง data pack

สร้างไฟล์ข้อมูลกลางที่ `<งวด>/output/dashboard-data/flowaccount-<งวด>.json`
ตามสัญญาใน `references/dashboard-layout.md` แล้วดึงทีละบล็อก

> ด่านตรวจหลังเขียนไฟล์จะ **เตือน** ว่าไฟล์ `.json` ไม่มีหัวระบุ plugin + เวอร์ชัน —
> เป็นคำเตือนที่คาดไว้แล้วและไม่บล็อก เพราะ JSON ใส่คอมเมนต์ไม่ได้
> ที่มาของ data pack อยู่ใน `meta` และ `source` ของแต่ละบล็อกแทน
> ส่วนไฟล์ที่ต้องมีหัวจริง ๆ คือ `.xlsx` ซึ่งสคริปต์ใส่ให้เองจาก `plugin.json`

กฎการดึง:
- **หนึ่งบล็อกหนึ่งการเรียก** แล้วเขียนผลลงไฟล์ทันที ไม่กองผลดิบทั้งหมดไว้ใน context
- **บันทึก `source` ของทุกบล็อก**: ชื่อ tool, พารามิเตอร์ที่ส่งจริง, เวลาที่ดึง
  ตัวเลขที่ไม่รู้ที่มา เอาไปใช้ตัดสินใจไม่ได้
- **ผลลัพธ์ยาว** (สมุดรายวัน รายการเอกสาร) → สรุปเป็นยอดรวม/จัดอันดับก่อนเก็บ
  และถ้าดึงไม่หมดทุกหน้า ให้ตั้ง `status: "partial"` พร้อมบอกว่าดึงได้กี่หน้าจากกี่หน้า
- **tool error / timeout / ไม่มีสิทธิ์** → `status: "unavailable"` พร้อม `reason` ตามจริง
  **ห้ามเขียน 0 ห้ามข้าม ห้ามเดาจากบล็อกอื่น**
- ถ้าผลลัพธ์กินหลายหน้าและอยากประหยัด context ให้ส่งงานค้นให้ `flowaccount-lookup`
  (ไม่มี tool เขียน ปลอดภัยแม้สั่งผิด) แล้วเอาตัวเลขสรุปที่มันตอบมาใส่ data pack
  — **แต่ต้องบันทึกใน `source` ว่าได้ตัวเลขมาทางนั้น**

### Step 4 — ตรวจยอดข้ามแหล่งก่อนออกไฟล์

ใส่รายการตรวจใน `checks` ของ data pack อย่างน้อย 3 ข้อ:

| ตรวจอะไร | แหล่ง ก | แหล่ง ข |
|---|---|---|
| รายได้ของงวด | งบกำไรขาดทุน | ยอดรวมสมุดรายวันขาย |
| ค่าใช้จ่ายของงวด | งบกำไรขาดทุน | ยอดรวมรายการค่าใช้จ่าย |
| ลูกหนี้คงเหลือ | งบแสดงฐานะการเงิน | ยอดรวมอายุลูกหนี้ |

**ไม่ตรงคือข้อมูล ไม่ใช่ข้อผิดพลาดที่ต้องกลบ** — สคริปต์จะแสดงผลต่างไว้ในไฟล์
หน้าที่ของคุณคืออธิบายสาเหตุที่เป็นไปได้ (เอกสารรออนุมัติ เกณฑ์เงินสด/ค้างรับ ช่วงวันที่ต่างกัน)
**ห้ามปรับตัวเลขฝั่งใดฝั่งหนึ่งให้ตรงกัน**

### Step 5 — สร้างไฟล์ Excel ด้วยสคริปต์

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/skills/flowaccount-dashboard/scripts/build_dashboard.py" \
  "<งวด>/output/dashboard-data/flowaccount-<งวด>.json" \
  --out "<งวด>/output/dashboard-flowaccount-<งวด>.xlsx"
```

**ห้ามเขียนโค้ด openpyxl ขึ้นมาใหม่เอง** — สคริปต์นี้คือสิ่งที่ทำให้ไฟล์หน้าตาเหมือนกันทุกครั้ง
และเป็นตัวที่ทำให้ "ดึงไม่ได้" ไม่กลายเป็น 0 เงียบๆ

ถ้าเครื่องไม่มี `openpyxl` สคริปต์จะบอกวิธีติดตั้งแล้วออกด้วย exit code 3 —
แจ้งผู้ใช้ให้ติดตั้ง `python3 -m pip install --user openpyxl` **อย่าเปลี่ยนไปเขียน .csv แทนเงียบๆ**

สคริปต์จะพิมพ์: จำนวนบล็อกที่ดึงไม่ได้ · กราฟที่ไม่ได้วาง · การตรวจยอดที่ไม่ผ่าน
**ทั้งสามอย่างต้องถูกยกไปอยู่ในสรุปในแชตด้วย** อย่าปล่อยให้อยู่แต่ใน output ของสคริปต์

### Step 6 — สรุปในแชต

```
Dashboard FlowAccount — <ลูกค้า> งวด <งวด> (เทียบ <งวดก่อน>)

รายได้     : X บาท (+Y%)
ค่าใช้จ่าย : X บาท (+Y%)
กำไรสุทธิ  : X บาท (+Y%)
ลูกหนี้คงค้าง / เจ้าหนี้คงค้าง : X / X บาท

บล็อกที่ดึงไม่ได้ : N — <ชื่อบล็อก> เพราะ <เหตุผล>
การตรวจยอดที่ไม่ผ่าน : N — <รายการ> ต่าง X บาท
ไฟล์: <path>
```

ปิดท้ายด้วย **ข้อที่ผู้ใช้ต้องรู้ก่อนเอาไปใช้**: ตัวเลขเป็นค่า ณ เวลาที่ดึง ·
เอกสารที่ยังรออนุมัติใน ERP รวมอยู่ในยอดหรือไม่ · ยังไม่ได้กระทบยอดธนาคาร (ถ้ายัง)

## Edge cases ที่เจอจริง

| สถานการณ์ | วิธีจัดการ |
|---|---|
| ค่า default ของช่วงวันที่ไม่เหมือนกันทุก tool | ส่งพารามิเตอร์งวดเองทุกครั้ง แล้วบันทึกไว้ใน `source` |
| งบกำไรขาดทุนยังไม่ปิดงวด ตัวเลขขยับได้ | ระบุในชีตแดชบอร์ดว่าเป็นตัวเลขก่อนปิดงวด |
| เอกสารสถานะรออนุมัติ | บอกให้ชัดว่ายอดรวม**รวมหรือไม่รวม** เอกสารรออนุมัติ — อย่าปล่อยให้เดา |
| กิจการมีหลายสกุลเงิน | ดึง `list_company_currencies` ก่อน ถ้ามีมากกว่า 1 ให้ทำเฉพาะ THB แล้วแจ้งข้อจำกัด |
| ยอดในงบทดลองไม่เท่ากันสองด้าน | รายงานตามจริง — เป็นสัญญาณว่าข้อมูลในระบบยังไม่เรียบร้อย |
| รายการมากเกินกว่าจะดึงครบ | `status: "partial"` + จัดอันดับเฉพาะรายใหญ่ ห้ามทำเหมือนดึงครบ |
| ผู้ใช้ขอ "งวดนี้" ตอนวันที่ 1 ของเดือน | ถามยืนยันว่าหมายถึงเดือนปัจจุบันที่แทบไม่มีข้อมูล หรือเดือนก่อน |
| ปีในคำขอเป็น พ.ศ. | แปลงเป็น ค.ศ. ก่อนส่ง แล้วแสดงทั้งสองแบบให้ผู้ใช้ยืนยัน |

## ข้อจำกัดและสิ่งที่ผู้ใช้ต้องตรวจเอง

- **ตัวเลขทั้งหมดคือสิ่งที่ FlowAccount รายงาน ณ เวลาที่ดึง** — ไม่ใช่งบการเงินที่ตรวจสอบแล้ว
  ถ้าข้อมูลในระบบยังลงไม่ครบ Dashboard ก็ไม่ครบตามไปด้วย และ skill นี้ไม่มีทางรู้ว่าอะไรยังไม่ได้ลง
- **ไม่ได้กระทบยอดกับเอกสารต้นทางหรือ statement ธนาคาร** — ใช้ `/bank-reconcile` แยก
- ช่อง `ดึงไม่ได้` หมายถึงดึงไม่ได้จริง ๆ **ห้ามอ่านเป็นศูนย์** และต้องตามให้ครบก่อนส่งรายงานผู้บริหาร
- อัตราส่วนและ % เปลี่ยนแปลงเป็นค่าที่ **สคริปต์คำนวณต่อ** จากตัวเลขที่ดึงมา
  ไม่ใช่ค่าที่ ERP รายงาน — ถ้าสองฝั่งไม่ตรงกัน ให้เชื่อ ERP
- **ไม่ตรวจความถูกต้องทางบัญชีของตัวเลขที่ดึงมา** ไม่ตรวจว่ารายการถูกลงผังบัญชีถูกต้อง
  และ **ไม่ตรวจจับการทุจริต**
- การตรวจยอดข้ามแหล่งบอกได้แค่ว่าตัวเลขสองแหล่งตรงกันหรือไม่ **ไม่ได้บอกว่าฝั่งไหนถูก**
