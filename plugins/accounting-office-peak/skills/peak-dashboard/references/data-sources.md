# แหล่งข้อมูลของแต่ละบล็อก — PEAK MCP

> ⚠️ **ไฟล์นี้ตั้งใจไม่ระบุชื่อ tool ของ PEAK**
> ชุด tool ของ PEAK MCP ยังไม่ได้ยืนยันกับ endpoint จริง การเขียนชื่อไว้ตายตัว
> จะทำให้ skill พังทั้งตัวเมื่อชื่อไม่ตรง และแย่กว่านั้นคือทำให้เดาชื่อ tool
> สิ่งที่เขียนไว้แทนคือ **งานที่ต้องหา tool ให้ได้** และ **วิธีตรวจว่า tool ที่เจอใช้ได้จริง**

---

## 1. ขั้นตอนสำรวจ tool (ทำทุกครั้งที่เริ่มงาน)

1. ดูรายชื่อ tool ของ MCP server `peak` ที่โหลดอยู่จริงในเซสชันนี้
2. จับคู่กับตารางงานด้านล่าง — จดชื่อ tool ที่เลือกไว้ เพราะต้องบันทึกลง `source` ของทุกบล็อก
3. tool ที่ไม่แน่ใจว่าอ่านอย่างเดียว **ห้ามลองยิงดู** ถามผู้ใช้ก่อน
4. รายชื่อ tool ที่เคยเจอจริงถูกบันทึกไว้ที่ `${CLAUDE_PLUGIN_DATA}/observed-tools.json`
   โดย `hooks/erp_post.py` — ใช้เป็นจุดเริ่มต้นได้
5. สรุปผลสำรวจให้ผู้ใช้เห็นเป็นตาราง **งาน → tool ที่จะใช้ → ได้/ไม่ได้** ก่อนเริ่มดึง

| งาน | ต้องมี tool ที่ทำอะไร | ใช้ทำบล็อก |
|---|---|---|
| ยืนยันกิจการปลายทาง | อ่านข้อมูลกิจการที่เชื่อมต่ออยู่ | หัวไฟล์ (บังคับ) |
| งบกำไรขาดทุน | ดึงงบกำไรขาดทุนตามช่วงเวลา | `pl` |
| งบแสดงฐานะการเงิน | ดึงงบแสดงฐานะการเงิน ณ วันที่ | `balance` |
| งบทดลอง / ยอดตามผังบัญชี | ดึงงบทดลอง หรือ list ผังบัญชีพร้อมยอด | `trial_balance` |
| อายุลูกหนี้ | รายงานอายุลูกหนี้ หรือ list ใบแจ้งหนี้ค้างรับพร้อมวันครบกำหนด | `ar_aging` |
| อายุเจ้าหนี้ | รายงานอายุเจ้าหนี้ หรือ list ใบค้างจ่ายพร้อมวันครบกำหนด | `ap_aging` |
| ยอดขาย | list เอกสารขายตามช่วงเวลา | `sales` |
| ค่าใช้จ่าย | list เอกสารค่าใช้จ่ายตามช่วงเวลา | `expense` |
| เงินรับ-จ่าย | list การรับ/จ่ายชำระ หรือสมุดรายวันรับ-จ่าย | `cash_in` / `cash_out` |
| คู่ค้า/ลูกค้า | ค้น contact ด้วยรหัสหรือชื่อ | `top_customers` / `top_vendors` |

**ถ้าไม่มี tool ยืนยันกิจการ → หยุดทั้งงาน** ห้ามดึงอะไรต่อ
บล็อกอื่นหาไม่ได้ → `status: "unavailable"` + `reason` ว่าไม่มี tool ที่ทำงานนั้น

## 2. เมื่อ tool ถูก deny โดยด่านตรวจ (learn-mode)

ด่านของ plugin นี้ **deny tool ที่ verb ยังไม่ได้จัดประเภท แม้จะเป็น tool อ่าน**
(ต่างจาก FlowAccount ที่แค่ถาม) ข้อความ deny จะบอกชื่อ `<namespace>__<action>` มาให้

สิ่งที่ต้องทำ:
1. ตรวจเองว่า tool นั้นอ่านอย่างเดียวจริง — ไม่ใช่การอนุมัติ ยกเลิก ลบ จ่ายชำระ
   ส่งอีเมล แชร์ อัปโหลด หรือปิดงวด
2. บอกผู้ใช้ให้เติมชื่อลงใน `read_tools` ของ `hooks/peak-tools.json`
   และเติมชุดเดียวกันใน `tools:` ของ `agents/peak-lookup.md`
3. ทำบล็อกนั้นเป็น `unavailable` ด้วย `reason` ว่า
   `tool <ชื่อ> ถูก deny โดยด่านตรวจ (learn-mode) — รอผู้ใช้ยืนยันว่าเป็น tool อ่าน`

**ห้ามแก้ `peak-tools.json` เองเด็ดขาด** — การขยายสิทธิ์ของตัวเองเป็นการตัดสินใจของผู้ใช้
และมันคือไฟล์เดียวที่กันการเขียนข้อมูลผิดพลาดเข้าระบบลูกค้าในตอนนี้

**และห้ามรายงานว่า "ไม่มีข้อมูล"** — สามอย่างนี้ต่างกันและแก้ต่างวิธีกัน:

| สิ่งที่เกิด | ความหมาย | ทางแก้ |
|---|---|---|
| ถูก deny | ด่านตรวจยังไม่รู้จัก tool | ผู้ใช้เติม `peak-tools.json` |
| ไม่มีสิทธิ์ | บัญชีที่เชื่อมต่อไม่มีสิทธิ์อ่านรายงานนั้น | ผู้ใช้แก้สิทธิ์ใน PEAK |
| ไม่มีข้อมูล | เรียกได้ แต่ระบบคืนค่าว่าง | ข้อมูลยังไม่ได้ลงในระบบ |

## 3. แปลงงวดให้เป็นพารามิเตอร์

**ส่งค่าช่วงเวลาเองทุกครั้ง อย่าพึ่งค่า default** เพราะค่า default ของแต่ละ tool ไม่เหมือนกัน
และถ้าไม่ส่งอะไรเลย บาง tool หมายถึง "ทุกรายการ" ไม่ใช่ "เดือนนี้"

- **ปี พ.ศ. → ค.ศ. ลบ 543 เสมอ** งวดที่สำนักงานเรียก `2569-09` คือเดือน 9 ปี 2026
- แสดงทั้ง พ.ศ. และ ค.ศ. ให้ผู้ใช้ยืนยันก่อนดึง แล้วบันทึกค่าที่ส่งจริงลง `source.params`
- ถ้า tool รับเป็นช่วงวันที่ ให้ส่งวันแรก-วันสุดท้ายของงวดแบบระบุชัด
  ไม่ใช่คำอย่าง "เดือนนี้" ที่แปลผลต่างกันได้
- งวดเทียบ: ไม่ระบุ → ใช้เดือนก่อนหน้า แล้วบอกผู้ใช้ว่าใช้อะไร
  (ธุรกิจที่มีฤดูกาลอาจอยากเทียบเดือนเดียวกันปีก่อน — **ผู้ใช้เป็นคนบอก ไม่ใช่เดาเอง**)

## 4. กับดักที่เจอจริง

1. **หลายกิจการในบัญชีเดียว** — ความเสี่ยงอันดับหนึ่งของ PEAK
   ยืนยันกิจการปลายทางก่อนทุกครั้ง และถ้า tool ใดรับพารามิเตอร์ระบุกิจการ ให้ส่งไปให้ชัด
   ไม่พึ่งกิจการที่ระบบเลือกไว้เป็นค่าเริ่มต้น
2. **`list_*` มีการแบ่งหน้า** — ยอดรวมจากหน้าเดียวคือยอดรวมที่ผิด
   ดึงให้ครบ หรือ `status: "partial"` พร้อมจำนวนหน้าที่ดึงได้
3. **เอกสารหลายสถานะ** (ร่าง / รออนุมัติ / อนุมัติแล้ว / ยกเลิก)
   ต้องรู้ว่ายอดที่ได้รวมสถานะไหน แล้วเขียนไว้ใน `meta.notes`
4. **เอกสารขายหลายชนิดทับซ้อนกัน** — นับซ้ำได้ง่าย เลือกชนิดที่ถือเป็น "ยอดขาย"
   ของลูกค้ารายนั้น (ดู `mapping-overrides.md`) แล้วระบุไว้ในหัวชีต
5. **ใบลดหนี้/ใบเพิ่มหนี้** ถ้าไม่หักออก ยอดขายจะสูงเกินจริง — ดึงมาด้วยหรือระบุว่าไม่ได้หัก
6. **ผังบัญชีเป็นของแต่ละกิจการ** — ห้ามใช้ชื่อ/รหัสบัญชีจากลูกค้ารายอื่นมาจัดกลุ่ม
7. **งบกับสมุดรายวันไม่ตรงกันเป็นเรื่องปกติ** เมื่อเกณฑ์การรับรู้ต่างกัน — รายงานผลต่าง ห้ามกลบ
8. **ยอดใน Dashboard ไม่ใช่ยอดที่ยื่นภาษี** — ฐานภาษีมีข้อแตกต่างของตัวเอง
