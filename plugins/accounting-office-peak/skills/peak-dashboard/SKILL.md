# Dashboard จาก PEAK → Excel

ดึงตัวเลขที่ PEAK รายงาน แล้วจัดเป็นไฟล์เดียวที่ผู้บริหารอ่านรู้เรื่อง
**อ่านอย่างเดียว ไม่เขียนอะไรกลับเข้า ERP เลย**

> plugin นี้ต้องใช้คู่กับ `accounting-office-core` — ถ้ายังไม่ได้ติดตั้ง ให้บอกผู้ใช้ก่อน

---

## กฎบังคับ

กฎ 🔒 บังคับด้วย hook ของ plugin — ทำผิดแล้ว tool call จะถูกปฏิเสธ ไม่ใช่แค่คำเตือน

| กฎ | บังคับโดย |
|---|---|
| ทำงานได้ทีละลูกค้า — โฟลเดอร์รายอื่นถูกบล็อกทั้ง session | 🔒 hook |
| ต้องอ่าน `client-profile.md` ก่อน จึงจะแตะโฟลเดอร์ลูกค้าได้ | 🔒 hook |
| เขียนได้เฉพาะ `<งวด>/output/` — `ocr-output/` `source-docs/` `bank/` อ่านอย่างเดียว | 🔒 hook |
| tool ที่เป็นการอนุมัติ / ยกเลิก / ลบ / จ่ายชำระ / ส่งอีเมล / แชร์ ถูก deny | 🔒 hook |
| ขณะทำงานลูกค้า ห้ามต่อเน็ต/ใช้ MCP ที่ไม่ใช่ ERP/ส่งอีเมล (PDPA) | 🔒 hook |
| ไฟล์ `.xlsx` ต้องมีหัวระบุ plugin + เวอร์ชัน | 🔒 hook (เตือนหลังเขียน — สคริปต์ใส่ให้เองแล้ว) |

> ⚠️ **ด่านตรวจของ PEAK ทำงานแบบ learn-mode** — tool ที่ verb ไม่ชัดเจนจะถูก **deny ไม่ใช่ถาม**
> แม้จะเป็น tool อ่านก็ตาม ถ้าเจอ deny ให้อ่านหัวข้อ "เมื่อ tool อ่านถูก deny" ด้านล่าง
> **"ถูก deny" ไม่ใช่ "ไม่มีข้อมูล"** — การสับสนสองอย่างนี้ทำให้ Dashboard มีช่องว่างที่ไม่มีใครรู้ว่าทำไม

ที่เหลือเป็นเรื่องที่ต้องใช้วิจารณญาณ — hook ตรวจแทนไม่ได้:

- **ห้ามเดาตัวเลข** ดึงไม่ได้ให้บันทึกว่าดึงไม่ได้ **ห้ามใส่ 0 แทน**
  ศูนย์ที่ไม่ใช่ศูนย์จริงคือความผิดพลาดที่แพงที่สุดของรายงานผู้บริหาร
- **ห้ามคำนวณตัวเลขที่ ERP รายงานมาแล้วใหม่เอง** — ถ้าคำนวณเพิ่ม ต้องกำกับว่าเป็นค่าที่คำนวณต่อ
- **ห้ามเดาชื่อ tool** — ดูรายชื่อที่โหลดอยู่จริงก่อนเสมอ
- **ถ้าไม่ระบุโฟลเดอร์ลูกค้า/งวด ให้ถามก่อน** อย่าเดา อย่าไล่สแกนทั้งเครื่อง

---

## ขอบเขต

**รองรับ**
- ดึงข้อมูลด้วย tool อ่านของ PEAK MCP ที่ **ยืนยันแล้วว่ามีจริงในเซสชันนี้**
- Dashboard 1 กิจการ 1 งวด เทียบกับ 1 งวดก่อนหน้า
- ชีตมาตรฐาน: แดชบอร์ด · งบกำไรขาดทุน · งบแสดงฐานะการเงิน · งบทดลอง · อายุลูกหนี้ ·
  อายุเจ้าหนี้ · ยอดขาย · ค่าใช้จ่าย · เงินรับ-จ่าย · ที่มาของข้อมูล
- กราฟในไฟล์ (แท่ง / เส้น / วงกลม) ที่อ้างเซลล์จริง

**ไม่รองรับ**
- เขียน แก้ อนุมัติ หรือลบอะไรใน PEAK (ใช้ `/post-expense-peak` สำหรับการบันทึก)
- รวมหลายกิจการไว้ในไฟล์เดียว — **ทำทีละกิจการ** (PEAK เข้าถึงหลายกิจการได้ในบัญชีเดียว)
- แปลงสกุลเงินและงบรวมกิจการ
- พยากรณ์ ประมาณการ หรือคำแนะนำทางธุรกิจ
- ตัวเลขทางภาษีที่ต้องยื่น (ภ.พ.30 ภ.ง.ด.) — ใช้ skill ของงานนั้นโดยเฉพาะ

---

## ขั้นตอนการทำงาน

### Step 0 — สำรวจ tool ที่มีจริง แล้วจับคู่งานเอง (สำคัญที่สุดใน skill นี้)

**เอกสารนี้ไม่ระบุชื่อ tool ของ PEAK ไว้ตายตัว** เพราะชุด tool ของ PEAK MCP
ยังไม่ได้ยืนยันกับ endpoint จริง ให้ดูรายชื่อ tool ของ MCP server `peak` ที่โหลดอยู่จริง
แล้วจับคู่กับงานในตารางนี้ด้วยตัวเอง:

| งาน | ต้องมี tool ที่ทำอะไร | ถ้าไม่มี |
|---|---|---|
| ยืนยันกิจการปลายทาง | อ่านข้อมูลกิจการที่เชื่อมต่ออยู่ | **หยุดทั้งงาน** |
| งบกำไรขาดทุน | ดึงงบกำไรขาดทุนตามช่วงเวลา | บล็อกนั้น `unavailable` |
| งบแสดงฐานะการเงิน | ดึงงบแสดงฐานะการเงิน ณ วันที่ | บล็อกนั้น `unavailable` |
| งบทดลอง / ผังบัญชี | ดึงงบทดลองหรือยอดตามผังบัญชี | บล็อกนั้น `unavailable` |
| อายุลูกหนี้ / เจ้าหนี้ | ดึงรายงานอายุหนี้ หรือรายการค้างชำระที่มีวันครบกำหนด | บล็อกนั้น `unavailable` |
| ยอดขาย | list เอกสารขายตามช่วงเวลา | บล็อกนั้น `unavailable` |
| ค่าใช้จ่าย | list เอกสารค่าใช้จ่ายตามช่วงเวลา | บล็อกนั้น `unavailable` |
| เงินรับ-จ่าย | list การรับ/จ่ายชำระ หรือสมุดรายวันรับ-จ่าย | บล็อกนั้น `unavailable` |
| คู่ค้า/ลูกค้า | ค้น contact เพื่อแปลรหัสเป็นชื่อ | ใช้รหัสแทนชื่อ แล้วระบุไว้ |

**หา tool ยืนยันกิจการไม่ได้ → หยุด ไม่ต้องดึงอะไรเลย**
บล็อกอื่นหาไม่เจอ → ทำบล็อกนั้นเป็น `unavailable` พร้อมเหตุผลว่าไม่มี tool
**ห้ามข้ามไปเงียบๆ และห้ามเดาตัวเลขจากบล็อกอื่น**

ถ้ายังไม่ได้เชื่อมต่อ/authorize MCP server ให้แจ้งผู้ใช้ทำก่อน — **ทำแทนไม่ได้**

### เมื่อ tool อ่านถูก deny (learn-mode)

ด่านตรวจของ plugin นี้ deny tool ที่ยังไม่ได้จัดประเภท แม้จะเป็น tool อ่าน
ข้อความ deny จะบอกชื่อ `<namespace>__<action>` มาให้ — ทางแก้:

1. ตรวจเองก่อนว่า tool นั้น **อ่านอย่างเดียวจริง** (ไม่ใช่การอนุมัติ ยกเลิก จ่ายชำระ หรือส่งข้อมูลออก)
2. บอกผู้ใช้ให้เติมชื่อนั้นลงใน `read_tools` ของ `hooks/peak-tools.json`
   และเติมชุดเดียวกันใน `tools:` ของ `agents/peak-lookup.md`
3. รายชื่อ tool ที่เจอจริงถูกบันทึกไว้ที่ `${CLAUDE_PLUGIN_DATA}/observed-tools.json` ใช้อ้างอิงได้

**ห้ามแก้ `peak-tools.json` ให้เอง** — การขยายสิทธิ์ของตัวเองเป็นการตัดสินใจของผู้ใช้
และระหว่างที่ยังไม่ได้เติม ให้ทำบล็อกนั้นเป็น `unavailable` พร้อม `reason` ว่า
`tool ถูก deny โดยด่านตรวจ (learn-mode) — ยังไม่ได้ยืนยันว่าเป็น tool อ่าน`

### Step 1 — โหลดบริบทและยืนยันกิจการปลายทาง

1. อ่าน `client-profile.md` และ `mapping-overrides.md`
2. ยืนยันว่า `ERP ที่ใช้` = PEAK ถ้าไม่ใช่ → **หยุด**
3. อ่านข้อมูลกิจการที่เชื่อมต่ออยู่ แล้วแสดงเทียบให้ผู้ใช้เห็น:

```
กิจการใน PEAK         : <ชื่อ>  เลขผู้เสียภาษี <13 หลัก>
ตาม client-profile.md : <ชื่อ>  เลขผู้เสียภาษี <13 หลัก>
ผล: ตรงกัน / ไม่ตรงกัน
```

**ไม่ตรง → หยุดทันที**

> ⚠️ **PEAK ให้ผู้ใช้หนึ่งคนเข้าถึงหลายกิจการได้** สำนักงานที่ดูแลลูกค้าหลายรายจึงเสี่ยงสูง
> ที่จะดึงข้อมูลผิดกิจการ และ Dashboard ของกิจการผิดรายอ่านดูสมเหตุสมผลทุกบรรทัด
> จนกว่าจะมีคนเอาไปใช้ตัดสินใจ — ข้อนี้ห้ามข้ามเด็ดขาด

4. ยืนยัน **งวดและงวดเทียบ** พร้อมรูปแบบพารามิเตอร์ที่จะส่งจริง (พ.ศ. → ค.ศ. ลบ 543)
   ดู `references/data-sources.md` — **ห้ามพึ่งค่า default ของ tool**

### Step 2 — ตกลงขอบเขตชีตกับผู้ใช้

แสดงผลการสำรวจ tool จาก Step 0 ว่า **บล็อกไหนทำได้ บล็อกไหนทำไม่ได้เพราะอะไร**
แล้วถามว่าจะเดินหน้าด้วยชุดที่ทำได้ หรือรอเติม `peak-tools.json` ก่อน
การถามข้อนี้สำคัญ เพราะ Dashboard ที่ขาดครึ่งหนึ่งอาจไม่คุ้มที่จะส่ง

### Step 3 — ดึงข้อมูลลง data pack

สร้างไฟล์ข้อมูลกลางที่ `<งวด>/output/dashboard-data/peak-<งวด>.json`
ตามสัญญาใน `references/dashboard-layout.md` แล้วดึงทีละบล็อก

> ด่านตรวจหลังเขียนไฟล์จะ **เตือน** ว่าไฟล์ `.json` ไม่มีหัวระบุ plugin + เวอร์ชัน —
> เป็นคำเตือนที่คาดไว้แล้วและไม่บล็อก เพราะ JSON ใส่คอมเมนต์ไม่ได้
> ที่มาของ data pack อยู่ใน `meta` และ `source` ของแต่ละบล็อกแทน
> ส่วนไฟล์ที่ต้องมีหัวจริง ๆ คือ `.xlsx` ซึ่งสคริปต์ใส่ให้เองจาก `plugin.json`

กฎการดึง:
- **หนึ่งบล็อกหนึ่งการเรียก** แล้วเขียนผลลงไฟล์ทันที ไม่กองผลดิบไว้ใน context
- **บันทึก `source` ของทุกบล็อก**: ชื่อ tool ที่เรียกจริง, พารามิเตอร์, เวลาที่ดึง
- **ผลลัพธ์ยาว** → สรุปเป็นยอดรวม/จัดอันดับก่อนเก็บ ถ้าดึงไม่ครบทุกหน้า ให้ `status: "partial"`
  พร้อมบอกว่าได้กี่หน้าจากกี่หน้า
- **error / timeout / ไม่มีสิทธิ์ / ถูก deny** → `status: "unavailable"` + `reason` ตามจริง
  **แยกให้ชัดว่าเป็นกรณีไหน** เพราะ 4 อย่างนี้แก้ต่างวิธีกันหมด
- งานค้นที่ผลลัพธ์ยาว ส่งให้ `peak-lookup` ได้ — แต่ **ถ้ามันตอบว่า "ยังตั้งค่าไม่เสร็จ"
  นั่นไม่ใช่ "ไม่พบข้อมูล"** ให้แจ้งผู้ใช้ให้เติม `tools:` ของ agent ก่อน

### Step 4 — ตรวจยอดข้ามแหล่งก่อนออกไฟล์

ใส่ `checks` อย่างน้อย 3 ข้อ: รายได้ (งบกำไรขาดทุน ↔ ยอดรวมเอกสารขาย) ·
ค่าใช้จ่าย (งบกำไรขาดทุน ↔ ยอดรวมเอกสารค่าใช้จ่าย) ·
ลูกหนี้ (งบแสดงฐานะการเงิน ↔ ยอดรวมอายุลูกหนี้)

**ไม่ตรงคือข้อมูล ไม่ใช่ข้อผิดพลาดที่ต้องกลบ** — อธิบายสาเหตุที่เป็นไปได้
(เอกสารรออนุมัติ เกณฑ์การรับรู้ ช่วงวันที่ต่างกัน) **ห้ามปรับตัวเลขฝั่งใดให้ตรงกัน**

### Step 5 — สร้างไฟล์ Excel ด้วยสคริปต์

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/skills/peak-dashboard/scripts/build_dashboard.py" \
  "<งวด>/output/dashboard-data/peak-<งวด>.json" \
  --out "<งวด>/output/dashboard-peak-<งวด>.xlsx"
```

**ห้ามเขียนโค้ด openpyxl ขึ้นมาใหม่เอง** — สคริปต์นี้คือสิ่งที่ทำให้ไฟล์หน้าตาเหมือนกันทุกครั้ง
และเป็นตัวที่ทำให้ "ดึงไม่ได้" ไม่กลายเป็น 0 เงียบๆ

ไม่มี `openpyxl` → สคริปต์บอกวิธีติดตั้งแล้วออกด้วย exit code 3
แจ้งผู้ใช้ให้ติดตั้ง **อย่าเปลี่ยนไปเขียน .csv แทนเงียบๆ**

สคริปต์จะพิมพ์: บล็อกที่ดึงไม่ได้ · กราฟที่ไม่ได้วาง · การตรวจยอดที่ไม่ผ่าน
**ทั้งสามอย่างต้องถูกยกไปอยู่ในสรุปในแชตด้วย**

### Step 6 — สรุปในแชต

```
Dashboard PEAK — <ลูกค้า> งวด <งวด> (เทียบ <งวดก่อน>)

รายได้     : X บาท (+Y%)
ค่าใช้จ่าย : X บาท (+Y%)
กำไรสุทธิ  : X บาท (+Y%)
ลูกหนี้คงค้าง / เจ้าหนี้คงค้าง : X / X บาท

บล็อกที่ดึงไม่ได้ : N — <ชื่อ> เพราะ <ไม่มี tool / ถูก deny / error / ไม่มีสิทธิ์>
การตรวจยอดที่ไม่ผ่าน : N — <รายการ> ต่าง X บาท
ไฟล์: <path>
```

ถ้ามีบล็อกที่ `unavailable` เพราะ **ถูก deny** ให้ปิดท้ายด้วยรายชื่อ tool ที่ต้องเติมใน
`peak-tools.json` เพื่อให้รันครั้งหน้าได้ครบ

## Edge cases ที่เจอจริง

| สถานการณ์ | วิธีจัดการ |
|---|---|
| tool อ่านถูก deny โดย learn-mode | `unavailable` + บอกชื่อ tool ที่ต้องเติม — **ไม่ใช่ "ไม่มีข้อมูล"** |
| `peak-lookup` ตอบว่ายังตั้งค่าไม่เสร็จ | แจ้งให้เติม `tools:` ของ agent ห้ามตีความว่าไม่พบข้อมูล |
| ผู้ใช้เข้าถึงหลายกิจการ | ยืนยันกิจการปลายทางก่อนทุกครั้ง ทำทีละกิจการ |
| ค่า default ของช่วงวันที่ไม่เหมือนกันทุก tool | ส่งพารามิเตอร์งวดเองทุกครั้ง แล้วบันทึกไว้ใน `source` |

## ข้อจำกัดและสิ่งที่ผู้ใช้ต้องตรวจเอง

- **ตัวเลขทั้งหมดคือสิ่งที่ PEAK รายงาน ณ เวลาที่ดึง** — ไม่ใช่งบการเงินที่ตรวจสอบแล้ว
  ถ้าข้อมูลในระบบยังลงไม่ครบ Dashboard ก็ไม่ครบตามไปด้วย และ skill นี้ไม่มีทางรู้
- **ชุด tool ของ PEAK MCP ยังไม่ได้ยืนยันกับ endpoint จริง** — บล็อกที่ทำได้จริง
  ขึ้นกับ tool ที่มีในเซสชันนั้นและรายชื่อที่ผู้ใช้ยืนยันไว้ใน `peak-tools.json`
  **รันสองครั้งต่างเวลาอาจได้จำนวนชีตไม่เท่ากัน** — ชีตที่มาของข้อมูลคือที่ที่บอกว่าครั้งนี้ได้อะไรมา
- **ไม่ได้กระทบยอดกับเอกสารต้นทางหรือ statement ธนาคาร** — ใช้ `/bank-reconcile` แยก
- ช่อง `ดึงไม่ได้` หมายถึงดึงไม่ได้จริง ๆ **ห้ามอ่านเป็นศูนย์**
- อัตราส่วนและ % เปลี่ยนแปลงเป็นค่าที่ **สคริปต์คำนวณต่อ** ถ้าไม่ตรงกับที่ ERP แสดง ให้เชื่อ ERP
- **ไม่ตรวจความถูกต้องทางบัญชีของตัวเลขที่ดึงมา** ไม่ตรวจการลงผังบัญชี
  และ **ไม่ตรวจจับการทุจริต**
- การตรวจยอดข้ามแหล่งบอกได้แค่ว่าสองแหล่งตรงกันหรือไม่ **ไม่ได้บอกว่าฝั่งไหนถูก**
- ข้อมูลถูกดึงออกจากระบบ PEAK ผ่าน MCP และไฟล์ผลมีข้อมูลทางการเงินของลูกค้าตาม PDPA
  — เก็บไว้ในโฟลเดอร์ลูกค้าบนเครื่องสำนักงานเท่านั้น ห้ามส่งออกนอกเครื่อง
