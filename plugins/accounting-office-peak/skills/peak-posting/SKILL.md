# บันทึกค่าใช้จ่ายเข้า PEAK

ขั้นสุดท้ายของสายงาน: รายการที่ตรวจแล้ว → เอกสารใน PEAK **สถานะรออนุมัติ**

> plugin นี้ต้องใช้คู่กับ `accounting-office-core` — ถ้ายังไม่ได้ติดตั้ง ให้บอกผู้ใช้ก่อน

---

## กฎบังคับ (ทุก skill ในชุดนี้ใช้เหมือนกัน)

1. **ทำงานเฉพาะในโฟลเดอร์ลูกค้าที่ผู้ใช้ระบุ** ห้ามอ่านหรือเขียนโฟลเดอร์ลูกค้ารายอื่น
2. **อ่าน `client-profile.md` ก่อนเริ่มงานทุกครั้ง** ถ้าไม่มี ให้หยุดแล้วบอกผู้ใช้ให้รัน `/new-client` ก่อน
3. **ก่อน action ที่เขียนข้อมูลเข้า ERP** ต้องแสดงชื่อบริษัทและเลขผู้เสียภาษีของบริษัทปลายทางใน ERP แล้วเทียบกับ `client-profile.md` — ถ้าไม่ตรง **หยุดทันที**
4. **สร้างเอกสารใน ERP เป็นสถานะรออนุมัติเท่านั้น** ห้ามอนุมัติ ห้ามบันทึกรับชำระ ห้าม void ห้ามลบ
5. **ใส่ชื่อ plugin และเลขเวอร์ชันไว้ในหัวทุกไฟล์ที่สร้าง** เช่น `accounting-office-peak v1.0.0 — 2569-09-16`

---

## หลักการที่ห้ามละเมิดเพิ่มเติม

1. **ห้ามสร้างเอกสารโดยไม่ผ่านการอนุมัติของผู้ใช้** — preview ทั้งกองก่อนเสมอ
2. **ห้ามสร้างคู่ค้าใหม่ก่อนค้นหาให้ครบทุกวิธี**
3. **ห้ามบันทึกทับเอกสารที่มีอยู่แล้ว** — ตรวจซ้ำทุกใบ
4. **ห้ามเดารหัสผังบัญชี** ถ้าความมั่นใจต่ำกว่า 80% → ถามผู้ใช้
5. **ถ้าไม่มีอะไรต้องบันทึก ให้บอกตรงๆ**
6. **ถ้า response ช้าหรือหลุด ห้ามยิงซ้ำ** — ตรวจก่อนว่าเอกสารถูกสร้างไปแล้วหรือยัง

---

## ขอบเขต

**รองรับ** — เอกสารฝั่งซื้อ/ค่าใช้จ่าย ที่ผ่าน `/review-ocr` หรือ `/vouch-expense` แล้ว

**ไม่รองรับ**
- เอกสารฝั่งขาย, การอนุมัติ, การบันทึกรับ/จ่ายชำระ, void, ลบเอกสาร
- การแก้ไขผังบัญชี การสร้างรหัสบัญชีใหม่
- การปิดงวดหรือปรับปรุงรายการปิดบัญชีใน PEAK

---

## ขั้นตอนการทำงาน

### Step 0 — สำรวจ tool ที่มีจริง (สำคัญมาก)

**ก่อนเรียก tool ใดๆ ให้ดูรายชื่อ tool ของ MCP server `peak` ที่โหลดอยู่จริงในเซสชันนี้ก่อน
แล้วจับคู่ tool กับงานแต่ละขั้นด้วยตัวเอง**

เอกสารนี้ **ไม่ระบุชื่อ tool ตายตัว** เพราะชุด tool ของ PEAK MCP อาจต่างจากที่ทดสอบไว้
งานที่ต้องหา tool ให้ได้:

| งาน | ต้องมี tool ที่ทำอะไร |
|---|---|
| ยืนยันกิจการปลายทาง | อ่านข้อมูลกิจการ/บริษัทที่เชื่อมต่ออยู่ |
| ดึงผังบัญชี | list ผังบัญชีของกิจการนั้น |
| ค้นคู่ค้า | ค้น contact/vendor ด้วยเลขผู้เสียภาษีและชื่อ |
| ตรวจเอกสารซ้ำ | ค้นเอกสารค่าใช้จ่ายด้วยเลขที่อ้างอิง/ยอด/วันที่ |
| สร้างเอกสาร | สร้างเอกสารค่าใช้จ่าย |

**ถ้าหา tool สำหรับงานใดไม่เจอ ให้หยุดแล้วแจ้งผู้ใช้ว่าทำขั้นนั้นไม่ได้
ห้ามข้ามขั้นนั้นแล้วบันทึกต่อ** โดยเฉพาะขั้นยืนยันกิจการและขั้นตรวจเอกสารซ้ำ

ถ้ายังไม่ได้เชื่อมต่อ/authorize MCP server ให้แจ้งผู้ใช้ทำก่อน — **ทำแทนไม่ได้**

### Step 1 — โหลดบริบทและตรวจกิจการปลายทาง

1. อ่าน `client-profile.md` และ `mapping-overrides.md`
2. ยืนยันว่า `ERP ที่ใช้` = PEAK ถ้าไม่ใช่ → **หยุด**
3. อ่านข้อมูลกิจการที่เชื่อมต่ออยู่จาก PEAK
4. **แสดงให้ผู้ใช้เห็นชัดๆ แล้วเทียบ:**

```
กิจการปลายทางใน PEAK  : <ชื่อ>  เลขผู้เสียภาษี <13 หลัก>
ตาม client-profile.md : <ชื่อ>  เลขผู้เสียภาษี <13 หลัก>
ผล: ตรงกัน / ไม่ตรงกัน
```

**ไม่ตรง → หยุดทันที**

> ⚠️ PEAK ให้ผู้ใช้หนึ่งคนเข้าถึง **หลายกิจการ** ได้ — สำนักงานบัญชีที่ดูแลลูกค้าหลายราย
> มีความเสี่ยงสูงที่จะบันทึกผิดกิจการ ข้อนี้ห้ามข้ามเด็ดขาด

5. ดึงผังบัญชีของกิจการนั้นมาไว้ใช้จับคู่ — **ห้ามใช้ผังบัญชีจากลูกค้ารายอื่น**

### Step 2 — เตรียมรายการ

คัดเฉพาะแถวที่ผ่านการตรวจ รายการที่ยังติด `ไม่พบเอกสาร` / `ต้องแก้` → **ไม่บันทึก**
แล้วรายงานแยกว่าข้ามกี่ใบเพราะอะไร

ตรวจคณิตศาสตร์ทุกใบ:
```
|ยอดก่อน VAT × 0.07 − VAT| ≤ 0.02
ยอดก่อน VAT + VAT = ยอดรวม
WHT (ถ้ามี) คำนวณจากยอดก่อน VAT ไม่ใช่ยอดรวม
```
ไม่ตรง → ไม่บันทึกใบนั้น แจ้งผู้ใช้

### Step 3 — กันเอกสารซ้ำ

ค้นเอกสารที่มีอยู่ด้วยเลขที่เอกสารของผู้ขายก่อน ถ้าไม่เจอให้ค้นด้วยชื่อคู่ค้า + ยอดรวม + วันที่

**ถือว่าซ้ำเมื่อตรงครบ 3 อย่าง**: เลขที่เอกสารผู้ขาย + ยอดรวม + วันที่เอกสาร
→ ข้ามใบนั้น รายงานว่า "ซ้ำ — บันทึกไว้แล้วที่ `<เลขที่เอกสารในระบบ>`"

### Step 4 — กันคู่ค้าซ้ำ

ค้นตามลำดับ **ห้ามข้ามขั้น**:
1. เลขผู้เสียภาษี 13 หลัก
2. คำสั้นๆ ในชื่อ (partial match)
3. ชื่อภาษาอังกฤษ

เจอ 1 ราย → ใช้รายนั้น · เจอหลายราย → เลือกรายที่ข้อมูลครบแล้วแจ้งผู้ใช้ว่ามีซ้ำ ·
ไม่เจอ → ทำเครื่องหมาย "คู่ค้าใหม่" ใน preview ให้ผู้ใช้เห็นก่อนสร้าง

**ที่อยู่ต่างกันไม่ใช่เหตุผลให้สร้างคู่ค้าใหม่**

### Step 5 — จับคู่รหัสผังบัญชีและประเภทภาษี

- รหัสผังบัญชี → `references/account-code-mapping.md`
- ประเภท VAT และการตั้งค่าราคารวม/ไม่รวม VAT → `references/vat-type.md`
- อัตราภาษีหัก ณ ที่จ่าย → `accounting-office-core` → `skills/wht-prep/references/wht-rates.md`

`mapping-overrides.md` ของลูกค้า **ชนะ** กฎ default เสมอ
ความมั่นใจ < 80% → ใส่ ⚠️ พร้อมเสนอ 2 ตัวเลือกให้ผู้ใช้เลือก

### Step 6 — Preview (บังคับ)

แสดงทั้งกองพร้อมกัน:

| # | ไฟล์ | คู่ค้า | เลขที่ | วันที่ | รหัสบัญชี | ประเภท VAT | ก่อน VAT | VAT | WHT | ยอดจ่ายสุทธิ | สถานะ |
|---|---|---|---|---|---|---|---|---|---|---|---|

พร้อมยอดรวมทั้งกอง และ **ต้องถามผู้ใช้ 3 ข้อนี้เสมอ ไม่มีค่า default**:
- ราคาในเอกสาร **รวม VAT แล้ว** หรือ **ยังไม่รวม**
- **จ่ายเงินแล้ว** หรือ **ตั้งหนี้ค้างจ่าย**
- ถ้าจ่ายแล้ว จ่ายจากช่องทางไหน (แต่ **ห้ามบันทึกการจ่ายชำระเอง** — ดูข้อจำกัดด้านล่าง)

รอคำยืนยัน **ห้ามข้ามไป Step 7 เอง**

### Step 7 — บันทึกจริง

สร้างเอกสารทีละใบ เก็บเลขที่เอกสารที่ระบบออกให้ และรหัสอ้างอิงที่ response คืนมา

**ถ้า response ช้า หลุด หรือ timeout → ห้ามยิงซ้ำ**
ให้ค้นในระบบก่อนว่าเอกสารถูกสร้างไปแล้วหรือยัง แล้วค่อยตัดสินใจ

### Step 8 — สรุปและบันทึกผล

บันทึกที่ `<งวด>/output/post-peak-<งวด>.md`
หัวไฟล์: `<!-- accounting-office-peak v1.0.0 | <ลูกค้า> | <งวด> | <วันที่> -->`

| # | ไฟล์ต้นฉบับ | ผลลัพธ์ | เลขที่เอกสารในระบบ | หมายเหตุ |
|---|---|---|---|---|

สรุปในแชต: บันทึกใหม่ N ใบ / ข้ามเพราะซ้ำ M ใบ / ข้ามเพราะยังตรวจไม่ผ่าน K ใบ / ผิดพลาด J ใบ
พร้อมรายการที่ต้องให้คนตามต่อ: **คู่ค้าใหม่ที่สร้าง · รหัสบัญชีที่ไม่มั่นใจ ·
เอกสารทั้งหมดยังอยู่ในสถานะรออนุมัติ**

### Step 9 — ตรวจซ้ำหลังบันทึกเสร็จ

ค้นเอกสารค่าใช้จ่ายในช่วงวันที่ของงวดอีกครั้ง แล้วเทียบกับที่ตั้งใจบันทึก:
จำนวนที่เพิ่มขึ้น · เลขที่อ้างอิงซ้ำ · ยอดรวมตรงกับ preview หรือไม่

ไม่ตรง → **รายงานตามจริง** อย่าเดาว่าสำเร็จ

## เมื่อเกิดข้อผิดพลาด

1. **ไม่มีคำตอบ ≠ ไม่ได้สร้าง** — ตรวจก่อนเสมอ
2. **หยุดทั้งกอง** เมื่อไม่มีสิทธิ์ หรือกิจการปลายทางไม่ตรง
3. **ทำต่อได้** เมื่อเป็นปัญหาเฉพาะใบ แต่ต้องรวบรวมรายงานตอนท้าย
4. **ห้ามข้ามกลไกกันซ้ำเพื่อให้งานเดินต่อ**
5. เจอรหัสข้อผิดพลาดที่ไม่รู้จัก → **แสดงข้อความดิบให้ผู้ใช้เห็น** แล้วหยุด อย่าเดาความหมาย

---

## ข้อจำกัดและสิ่งที่ผู้ใช้ต้องตรวจเอง

- **เอกสารที่สร้างอยู่ในสถานะรออนุมัติ** ผู้ใช้ต้องตรวจและอนุมัติเองใน PEAK
- **skill นี้ไม่บันทึกการจ่ายชำระ** แม้ผู้ใช้จะบอกว่าจ่ายแล้ว — บันทึกเป็นตั้งหนี้
  แล้วให้ผู้ใช้ไปบันทึกจ่ายชำระเองใน PEAK (การจ่ายชำระกระทบบัญชีธนาคารโดยตรง)
- **รหัสผังบัญชีที่จับคู่ให้เป็นการอนุมาน** — ผู้ทำบัญชีต้องตรวจทุกใบ
- ไม่ตัดสินว่ารายจ่ายเป็นรายจ่ายต้องห้ามตามมาตรา 65 ตรี และไม่ตัดสินสิทธิขอคืนภาษีซื้อ
- การกันเอกสารซ้ำอาศัยเลขที่เอกสารของผู้ขาย — ถ้าเอกสารไม่มีเลขที่ หรือ OCR อ่านผิด
  **การกันซ้ำจะไม่ทำงาน**
- **ไม่แนบไฟล์เอกสารต้นฉบับ** — ใส่ path ไว้ในหมายเหตุแทน แล้วผู้ใช้แนบเองถ้าต้องการ
- ยอดคงเหลือและรายงานภาษีใน PEAK ต้องกระทบยอดเองอีกชั้น
- ข้อมูลถูกส่งออกไปยังระบบ PEAK ผ่าน MCP — ผู้ใช้รับผิดชอบ PDPA และการจัดการสิทธิ์เข้าถึง
