# สร้างลูกค้ารายใหม่

สร้างโครงโฟลเดอร์มาตรฐานสำหรับลูกค้ารายใหม่ **นอก plugin** เพื่อไม่ให้ถูกเขียนทับเมื่ออัปเดต plugin

ชื่อลูกค้า / รอบบัญชีที่ผู้ใช้ระบุ: `$ARGUMENTS`

---

## Step 1 — ยืนยันข้อมูลก่อนสร้าง

ถามผู้ใช้ให้ครบก่อนสร้างโฟลเดอร์ (ใช้ AskUserQuestion ได้) — **ห้ามเดา**:

| ข้อมูล | ตัวอย่าง | บังคับ |
|---|---|---|
| ชื่อบริษัทเต็ม | บริษัท ตัวอย่างเทรดดิ้ง จำกัด | ✅ |
| ชื่อย่อที่ใช้ตั้งชื่อโฟลเดอร์ | ตัวอย่างเทรดดิ้ง | ✅ |
| เลขประจำตัวผู้เสียภาษี 13 หลัก | 0105560000001 | ✅ |
| สำนักงานใหญ่ / สาขาที่ | 00000 | ✅ |
| จด VAT หรือไม่ | จด / ไม่จด | ✅ |
| ERP ที่ลูกค้าใช้ | FlowAccount / PEAK / Express / ไม่มี | ✅ |
| รอบบัญชี | ม.ค.–ธ.ค. | ✅ |
| งวดที่จะเริ่มทำ | 2569-09 | ✅ |
| เกณฑ์บัญชี | คงค้าง / เงินสด | ✅ |
| โฟลเดอร์แม่ที่จะสร้างไว้ | `./ลูกค้า/` | ✅ |

ตรวจ checksum เลข 13 หลักก่อนบันทึก — วิธีคำนวณอยู่ใน
`skills/ocr-review/references/tax-id-checksum.md` (นับจากรากของ plugin นี้) ถ้าไม่ผ่านให้แจ้งผู้ใช้และถามซ้ำ **อย่าสร้างโฟลเดอร์ทิ้งไว้**

## Step 2 — ตรวจว่าซ้ำหรือไม่

ถ้ามีโฟลเดอร์ชื่อนี้อยู่แล้ว **หยุด** แล้วถามผู้ใช้ว่าจะเพิ่มงวดใหม่ในลูกค้าเดิม หรือใช้ชื่ออื่น
ห้ามเขียนทับ `client-profile.md` หรือ `mapping-overrides.md` ที่มีอยู่เดิมเด็ดขาด

## Step 3 — สร้างโครงโฟลเดอร์

```
ลูกค้า/<ชื่อลูกค้า>/
├── client-profile.md
├── mapping-overrides.md
├── <งวด เช่น 2569-09>/
│   ├── ocr-output/      ← ไฟล์ผล OCR ดิบ
│   ├── source-docs/     ← ภาพ/PDF เอกสารต้นฉบับ
│   ├── bank/            ← statement และ GL เงินฝาก
│   └── output/          ← ไฟล์ผลลัพธ์ที่ skill สร้าง
```

`chart-of-accounts.xlsx` ให้ผู้ใช้วางเองภายหลัง — **ห้ามสร้างไฟล์ Excel เปล่าหลอกไว้**
ให้บอกผู้ใช้ว่าต้องวางไฟล์ผังบัญชีจริงจาก ERP ลงที่ `ลูกค้า/<ชื่อลูกค้า>/chart-of-accounts.xlsx`

## Step 4 — เขียน client-profile.md

ใช้ template นี้ (แทนค่าจริงทั้งหมด ห้ามเหลือ `<...>`):

```markdown
<!-- สร้างโดย accounting-office-core v1.1.0 -->

# ข้อมูลลูกค้า — <ชื่อบริษัทเต็ม>

| หัวข้อ | ค่า |
|---|---|
| ชื่อบริษัท | <ชื่อบริษัทเต็ม> |
| เลขประจำตัวผู้เสียภาษี | <13 หลัก ไม่มีขีด> |
| สำนักงานใหญ่/สาขา | <00000 หรือเลขสาขา> |
| สถานะ VAT | <จด VAT / ไม่จด VAT> |
| ERP ที่ใช้ | <FlowAccount / PEAK / Express / ไม่มี> |
| รหัสบริษัทใน ERP | <ถ้ามี> |
| รอบบัญชี | <ม.ค.–ธ.ค.> |
| เกณฑ์บัญชี | <คงค้าง / เงินสด> |
| ผู้ทำบัญชีที่รับผิดชอบ | <ชื่อ> |
| วันที่สร้างโปรไฟล์ | <YYYY-MM-DD> |

## ข้อตกลงเฉพาะลูกค้ารายนี้
- (เช่น ลูกค้าส่งเอกสารทาง LINE ทุกวันที่ 5, ไม่บันทึกค่าน้ำมันเข้าค่าใช้จ่ายบริษัท)

## ประวัติการเปลี่ยนแปลง
| วันที่ | เปลี่ยนอะไร | โดย |
|---|---|---|
| <YYYY-MM-DD> | สร้างโปรไฟล์ | <ชื่อ> |
```

## Step 5 — เขียน mapping-overrides.md

```markdown
<!-- สร้างโดย accounting-office-core v1.1.0 -->

# ข้อยกเว้นการ mapping เฉพาะ <ชื่อลูกค้า>

ไฟล์นี้ **ชนะ** ค่า default ใน skill เสมอ — ถ้าขัดกัน ให้ยึดไฟล์นี้

## ผู้ขาย → หมวดหมู่/ผังบัญชี
| ผู้ขาย | บันทึกเป็น | เหตุผล | ตั้งแต่ |
|---|---|---|---|
| | | | |

## อัตราภาษีหัก ณ ที่จ่ายที่ตกลงกันไว้
| ประเภทเงินได้ | อัตรา | เหตุผล |
|---|---|---|
| | | |

## รายการที่ห้ามบันทึกอัตโนมัติ (ต้องถามผู้ใช้ทุกครั้ง)
- (เช่น รายการเกิน 100,000 บาท, ค่าใช้จ่ายส่วนตัวกรรมการ)
```

## Step 6 — สรุปให้ผู้ใช้

แสดง tree ที่สร้างจริง + เตือน 2 ข้อ:
1. ต้องวาง `chart-of-accounts.xlsx` เอง
2. ถ้าลูกค้าใช้ FlowAccount/PEAK ต้องติดตั้ง plugin ของ ERP นั้นเพิ่ม
   (`accounting-office-flowaccount` หรือ `accounting-office-peak`)
