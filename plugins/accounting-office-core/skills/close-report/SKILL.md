# สรุปปิดงวด + ร่างอีเมลขอเอกสาร

รวมผลจากทุกขั้นในงวด แล้วตอบคำถามเดียว: **ปิดงวดนี้ได้หรือยัง ถ้ายัง ติดอะไร และต้องขออะไรจากใคร**

---

## กฎบังคับ

กฎ 🔒 บังคับด้วย hook ของ plugin — ทำผิดแล้ว tool call จะถูกปฏิเสธ ไม่ใช่แค่คำเตือน

| กฎ | บังคับโดย |
|---|---|
| ทำงานได้ทีละลูกค้า — โฟลเดอร์รายอื่นถูกบล็อกทั้ง session | 🔒 hook |
| ต้องอ่าน `client-profile.md` ก่อน จึงจะแตะโฟลเดอร์ลูกค้าได้ | 🔒 hook |
| เขียนได้เฉพาะ `<งวด>/output/` — `ocr-output/` `source-docs/` `bank/` อ่านอย่างเดียว | 🔒 hook |
| ห้ามเขียนทับ `client-profile.md` / `mapping-overrides.md` ที่มีอยู่ และห้ามสร้าง `chart-of-accounts.xlsx` | 🔒 hook |
| หัวไฟล์ระบุ plugin + เวอร์ชัน | 🔒 hook (เติมให้เองตอนเขียนลง `output/`) |

> `<เวอร์ชัน>` ในตัวอย่างข้างล่างคือเลขจริงจาก `plugin.json` — hook เติมให้ตอนเขียนไฟล์
> ไม่ต้องพิมพ์เอง และอย่า hardcode เลขเวอร์ชันลงในไฟล์ผลลัพธ์
| ขณะทำงานลูกค้า ห้ามต่อเน็ต/ใช้ MCP ที่ไม่ใช่ ERP/ส่งอีเมล (PDPA) | 🔒 hook |

ที่เหลือเป็นเรื่องที่ต้องใช้วิจารณญาณ — hook ตรวจแทนไม่ได้:

- **ห้ามเดา** ถ้าอ่านไม่ออกหรือไม่แน่ใจ ให้บันทึกว่าไม่แน่ใจแล้วถามผู้ใช้ อย่าเติมค่าให้ดูสมบูรณ์
- **ถ้าไม่ระบุโฟลเดอร์ลูกค้า/งวด ให้ถามก่อน** อย่าเดา อย่าไล่สแกนทั้งเครื่อง

---

## ข้อห้ามเฉพาะ skill นี้

- **ห้ามส่งอีเมล** — สร้างเป็นไฟล์ร่างเท่านั้น ผู้ใช้อ่าน แก้ และกดส่งเอง
- **ห้ามสรุปว่า "พร้อมปิดงวด" ถ้ายังมีรายการค้างที่ยังไม่มีคำอธิบาย** แม้จะเหลือน้อยก็ตาม
- **ห้ามเดาว่ารายการที่ไม่มีเอกสารคืออะไร** — ระบุว่าไม่ทราบ แล้วให้เป็นข้อที่ต้องถามลูกค้า

---

## ขั้นตอนการทำงาน

### Step 1 — เก็บผลจากทุกขั้น

อ่าน `client-profile.md` แล้วสแกน `<งวด>/output/` เก็บผลจากไฟล์เหล่านี้ (เท่าที่มี)

| ไฟล์ | ดึงอะไร |
|---|---|
| `exceptions.xlsx` | จำนวน "ต้องแก้" ที่ยังไม่ติ๊ก `แก้แล้ว` |
| `vouch-*.xlsx` | จำนวน `ไม่พบเอกสาร` + ยอดเงิน, เอกสารที่ยังไม่มีรายการรองรับ |
| `bank-recon-*.xlsx` | ผลต่างคงเหลือ, รายการค้างที่ยัง "ต้องสอบสวน", รายการที่ต้องบันทึกเพิ่มใน GL |
| `pnd3-*.txt` / `pnd53-*.txt` | จำนวนใบ ยอดภาษีที่หัก และว่าเตรียมครบหรือยัง |
| `post-*.md` (ถ้ามี plugin ERP) | จำนวนที่ post เข้า ERP แล้ว / ที่ยังไม่ได้ post |

**ถ้าขั้นไหนยังไม่ได้ทำเลย (ไม่มีไฟล์) ให้ระบุว่า "ยังไม่ได้ทำ" ไม่ใช่ "ผ่าน"**
นี่คือความต่างที่สำคัญที่สุดในรายงานนี้

### Step 2 — ประเมินสถานะ

| สถานะ | เงื่อนไข |
|---|---|
| ✅ พร้อมปิดงวด | ทุกขั้นทำครบ · ผลต่างกระทบยอด = 0 · ไม่มีรายการค้างที่อธิบายไม่ได้ · ไม่มีเอกสารขาด |
| ⚠️ ปิดได้แต่มีข้อสังเกต | ทุกขั้นทำครบ · มีรายการค้างที่ **อธิบายได้แล้ว** (เช่น เช็คที่ยังไม่ขึ้นเงิน) |
| ❌ ยังปิดไม่ได้ | มีขั้นที่ยังไม่ทำ · หรือมีเอกสารขาด · หรือผลต่างกระทบยอดไม่เป็นศูนย์ |

### Step 3 — ออกรายงานสรุป

บันทึกที่ `<งวด>/output/close-report-<งวด>.md`

**คำนวณ "เหลืออีกกี่วัน" จากวันที่จริงในระบบ** และถ้าเลยกำหนดแล้วให้เขียนว่า
`เลยกำหนด N วัน` พร้อมเตือนเรื่องเงินเพิ่มและค่าปรับ — อย่าเขียนเป็นเลขติดลบเฉยๆ

### Step 3.5 — ให้ผู้ตรวจอิสระตรวจรายงาน (แนะนำ)

ส่งรายงานที่เพิ่งเขียนให้ `maker-checker-reviewer` ตรวจ โดยส่งไปแค่
**path ของรายงาน + path ของโฟลเดอร์งวด** เท่านั้น

**ห้ามส่งคำอธิบายว่าเราสรุปสถานะแบบนั้นเพราะอะไร** — ผู้ตรวจต้องอ่านไฟล์ผลลัพธ์เองแล้วสรุปเอง
ถ้าส่งเหตุผลไปด้วย ผู้ตรวจจะเห็นด้วยกับเราโดยอัตโนมัติ และการตรวจจะไม่มีประโยชน์

สิ่งที่ผู้ตรวจควรจับได้: ขั้นที่ยังไม่ได้ทำแต่ถูกนับเป็นผ่าน · ผลต่างกระทบยอดที่ไม่เป็นศูนย์
แต่สถานะกลับเป็น ✅ · รายการค้างที่ไม่มีคำอธิบาย · จำนวนวันจนถึงกำหนดยื่นที่คำนวณผิด

ถ้าต้องการตรวจความเสี่ยงภาษีของงวดด้วย ให้ส่งรายการค่าใช้จ่ายให้ `tax-compliance-checker`
แล้วนำผลมาใส่ในส่วน "รายการที่ต้องจัดการก่อนปิดงวด"

### Step 4 — ร่างอีเมลขอเอกสาร

ทำเฉพาะเมื่อมีรายการในส่วน "เอกสารที่ยังขาดจากลูกค้า"

เรื่อง: ขอเอกสารประกอบการปิดบัญชีประจำงวด <งวด> — <ชื่อบริษัท>

**กฎการร่าง:**
- ระบุเอกสารให้เจาะจงพอที่ลูกค้าหาได้ — `ใบกำกับภาษีจากบริษัท ก. เลขที่ INV-001 วันที่ 5/9/2569`
  ดีกว่า `ใบกำกับภาษีเดือนกันยายน`
- เรียงตามยอดเงินมากไปน้อย
- **ไม่เกิน 15 รายการต่อฉบับ** ถ้ามากกว่านั้นให้แนบเป็นไฟล์ Excel แล้วอ้างถึงในอีเมล
- กำหนดวันที่ขอคืน = ก่อนกำหนดยื่นอย่างน้อย 3 วันทำการ
- เว้นช่อง `<...>` ที่ไม่ทราบไว้ตามจริง **ห้ามแต่งชื่อคนหรือวันที่ขึ้นมาเอง**

## ข้อจำกัดและสิ่งที่ผู้ใช้ต้องตรวจเอง

- รายงานนี้สรุปจาก **ไฟล์ผลลัพธ์ที่มีอยู่ในโฟลเดอร์งวดเท่านั้น** — งานที่ทำนอกระบบนี้จะไม่ปรากฏ
- **ไม่ได้ตรวจงบการเงิน** ไม่ตรวจว่ารายการปรับปรุงปิดงวดครบหรือไม่
  (ค่าเสื่อมราคา ค่าใช้จ่ายค้างจ่าย รายได้ค้างรับ ปรับปรุงสินค้าคงเหลือ ภาษีเงินได้รอตัดบัญชี)
- ไม่ตรวจยอดคงเหลือบัญชีอื่นนอกจากเงินฝากธนาคาร (ลูกหนี้ เจ้าหนี้ สินค้าคงเหลือ สินทรัพย์ถาวร)
- **ไม่คำนวณภาษีที่ต้องชำระ และไม่ยื่นแบบ**
- กำหนดเวลาที่แสดงเป็นกำหนดทั่วไป — วันหยุดราชการและประกาศขยายเวลาเฉพาะกาลต้องตรวจเองที่ rd.go.th
- **สถานะ ✅ พร้อมปิดงวด หมายถึงงานในขอบเขต skill ชุดนี้ครบแล้วเท่านั้น** ไม่ใช่การรับรองงบการเงิน
  ผู้ทำบัญชีและผู้สอบบัญชียังต้องใช้ดุลพินิจของตนเอง
