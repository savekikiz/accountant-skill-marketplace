# กระทบยอดธนาคาร — GL เงินฝาก × Bank Statement

จับคู่รายการสองฝั่ง แล้วตอบว่า **อะไรที่ยังไม่ตรง และไม่ตรงเพราะอะไร**
เป้าหมายปลายทางคืองบกระทบยอดที่อธิบายผลต่างได้ทุกบาท

## ขอบเขต

**รองรับ**
- GL เงินฝากธนาคาร และ statement รูปแบบ `.xlsx`, `.csv`, `.pdf`
- จับคู่ 1:1 (ยอดตรงภายใน tolerance)
- จับคู่ 1:1 ที่ผลต่างเป็นภาษีหัก ณ ที่จ่ายอัตรามาตรฐาน (1%, 2%, 3%, 5%)
- จับคู่ 1:หลายรายการ (หลาย GL รวมเป็น 1 ยอดใน statement หรือกลับกัน)
- ทั้งด้านรับ (deposit / credit) และด้านจ่าย (withdrawal / debit)
- **หนึ่งบัญชีธนาคารต่อการรันหนึ่งครั้ง** — ถ้าลูกค้ามีหลายบัญชี ให้ทำทีละบัญชี

**ไม่รองรับ**
- บัญชีสกุลเงินต่างประเทศและการแปลงอัตราแลกเปลี่ยน
- จับคู่หลายต่อหลาย (many:many)
- การบันทึกรายการปรับปรุงเข้า ERP ให้ — skill นี้ชี้ว่าอะไรไม่ตรงเท่านั้น
- บัญชีอื่นที่ไม่ใช่เงินฝากธนาคาร

## ขั้นตอนการทำงาน

### Step 1 — โหลดบริบทและยืนยัน mapping

1. อ่าน `client-profile.md` และ `mapping-overrides.md`
2. หาไฟล์ใน `<งวด>/bank/` — ถ้ามีหลายบัญชี **ถามว่าจะทำบัญชีไหน**
3. ถ้าเป็น PDF ให้ extract เป็นตารางก่อน (statement ที่มีเส้นตารางทับตัวเลขมักอ่านเพี้ยน — ถ้าธนาคารมี `.xlsx`/`.csv` ให้แนะนำใช้แทน)
4. **แสดง column ที่เจอทั้งสองฝั่งให้ผู้ใช้ยืนยัน** — วันที่ / จำนวนเงิน / คำอธิบาย / ด้านรับ-ด้านจ่าย / column WHT ถ้ามี
5. ยืนยันยอดยกมาต้นงวดของทั้งสองฝั่ง — ถ้าต้นงวดไม่ตรงกันอยู่แล้ว **หยุดและแจ้งผู้ใช้ก่อน**
   กระทบยอดงวดนี้จะไม่มีความหมายถ้ายกมาผิดตั้งแต่ต้น

### Step 2 — Normalize

- วันที่ → รูปแบบเดียวกัน และ **แปลง พ.ศ./ค.ศ. ให้ตรงกันทั้งสองฝั่ง**
- จำนวนเงิน → ตัวเลขทศนิยม 2 ตำแหน่ง ตัด comma ออก
- แยกด้านรับและด้านจ่ายออกจากกัน — **ห้ามจับคู่ข้ามด้าน**
- ตรวจหน่วยเงินให้ตรงกัน (บาท ไม่ใช่สตางค์)

### Step 3 — จับคู่ตามลำดับ

#### ลำดับ 1 — 1:1 ยอดตรง
เงื่อนไขครบทุกข้อ: ด้านเดียวกัน · ยอดต่าง ≤ 1 บาท · วันที่ห่าง ≤ ±3 วัน (ปรับได้)
ถ้ามีชื่อผู้โอน/ผู้รับทั้งสองฝั่ง ใช้ความคล้ายของชื่อเป็นตัวช่วยตัดสินเมื่อมีคู่แข่งหลายคู่

#### ลำดับ 2 — 1:1 ที่ผลต่างเป็นภาษีหัก ณ ที่จ่าย
เกิดเมื่อผู้จ่ายหัก WHT ก่อนโอน ทำให้เงินเข้าบัญชีน้อยกว่ายอดตามใบแจ้งหนี้

```
ยอดใน GL − ยอดใน statement = ยอด WHT
ตรวจว่า ยอด WHT ≈ ยอดก่อน VAT × อัตรามาตรฐาน (1%, 2%, 3%, 5%) ภายใน ±1 บาท
```
- ถ้ามี column WHT แยกใน GL → ใช้ค่านั้นตรงๆ **ไม่ต้องเดา**
- WHT เกิดที่ด้านรับเป็นหลัก แต่เจอด้านจ่ายได้ — ตรวจทั้งสองด้าน
- ทุกคู่ที่จับได้แบบนี้ ต้องระบุอัตราและยอดที่สันนิษฐานไว้ในหมายเหตุ

#### ลำดับ 3 — 1:หลายรายการ
หลายรายการรวมกันได้ยอดเดียวในอีกฝั่ง
- ต้องอยู่ในวันเดียวกัน หรือ ±3 วันจากวันที่ในอีกฝั่ง
- ผลรวมต่าง ≤ 1 บาท
- ถ้าไม่ลงตัว ลองหัก WHT อัตรามาตรฐานแล้วคำนวณใหม่
- **จำกัดขนาดชุดที่รวมได้** (เช่น ไม่เกิน 5 รายการ) มิฉะนั้นจะได้ผลรวมที่บังเอิญตรงจำนวนมาก

#### ลำดับ 4 — ค้างกระทบยอด
ที่เหลือคือรายการที่ต้องอธิบาย จัดประเภทให้ด้วย:

| ประเภท | ลักษณะ | ปกติหรือไม่ |
|---|---|---|
| เช็คจ่ายที่ยังไม่ขึ้นเงิน | มีใน GL ด้านจ่าย ไม่มีใน statement | ปกติ |
| เงินฝากระหว่างทาง | มีใน GL ด้านรับ ไม่มีใน statement | ปกติ |
| ค่าธรรมเนียมธนาคาร | มีใน statement ด้านจ่าย ไม่มีใน GL | ปกติ — ต้องบันทึกเพิ่ม |
| ดอกเบี้ยรับ | มีใน statement ด้านรับ ไม่มีใน GL | ปกติ — ต้องบันทึกเพิ่ม |
| ภาษีหัก ณ ที่จ่ายที่ถูกหักจากดอกเบี้ย | ยอดเล็ก ด้านจ่ายใน statement | ปกติ |
| เช็คคืน | รายการกลับด้านในวันใกล้กัน | ต้องตรวจ |
| **ไม่เข้าประเภทใดเลย** | | **ต้องสอบสวน** |

### Step 4 — ออกไฟล์ผล

บันทึกที่ `<งวด>/output/bank-recon-<ชื่อบัญชี>.xlsx`

**Sheet `RECONCILIATION`**

| Column | คำอธิบาย |
|---|---|
| `GL_วันที่` `GL_คำอธิบาย` `GL_จำนวนเงิน` `GL_WHT` | ฝั่ง GL |
| `BANK_วันที่` `BANK_คำอธิบาย` `BANK_จำนวนเงิน` | ฝั่ง statement |
| `สถานะ` | `ตรง 1:1` / `ตรง 1:1 (WHT)` / `ตรง 1:หลาย` / `ค้างกระทบยอด` |
| `กลุ่ม` | รหัสกลุ่มสำหรับ 1:หลาย เช่น `G001` |
| `ด้าน` | รับ / จ่าย |
| `ผลต่าง` | |
| `ประเภทรายการค้าง` | ตามตาราง Step 3 ลำดับ 4 |
| `หมายเหตุ` | เช่น `WHT 3% = 300.00 บาท (สันนิษฐาน)` |

**สี:** เขียว `#C6EFCE` ตรง 1:1 · ฟ้า `#BDD7EE` ตรง 1:หลาย · แดงอ่อน `#FFC7CE` ค้างกระทบยอด

**Sheet `งบกระทบยอด`** — รูปแบบที่ใช้ยื่นผู้สอบบัญชีได้

```
ยอดคงเหลือตาม Bank Statement ณ สิ้นงวด          X
  บวก  เงินฝากระหว่างทาง                         X
  หัก   เช็คจ่ายที่ยังไม่ขึ้นเงิน                  (X)
  บวก/หัก รายการอื่น (ระบุ)                       X
= ยอดคงเหลือที่ปรับแล้ว                           X

ยอดคงเหลือตาม GL ณ สิ้นงวด                        X
  บวก  ดอกเบี้ยรับที่ยังไม่บันทึก                  X
  หัก   ค่าธรรมเนียมธนาคารที่ยังไม่บันทึก           (X)
  บวก/หัก รายการอื่น (ระบุ)                        X
= ยอดคงเหลือที่ปรับแล้ว                            X

ผลต่างคงเหลือ (ต้องเป็น 0)                         X
```

ถ้าผลต่างคงเหลือ **ไม่เป็นศูนย์** ให้แสดงตัวเลขจริงพร้อมข้อความว่ายังกระทบยอดไม่ครบ
**ห้ามบังคับให้ลงตัวด้วยรายการ "ผลต่างอื่นๆ" ที่ไม่มีคำอธิบาย**

**Sheet `SUMMARY`** — หัวไฟล์ `accounting-office-core v<เวอร์ชัน> | ลูกค้า | บัญชี | งวด | วันที่สร้าง`,
จำนวนและ % แต่ละสถานะ, ยอดรวมสองฝั่ง, รายการที่ต้องบันทึกเพิ่มใน GL

**Sheet `GL_DATA` / `BANK_DATA`** — ข้อมูลต้นฉบับสองฝั่ง เพื่อตรวจย้อนกลับได้

### Step 5 — สรุปในแชต

สรุป % ที่จับคู่ได้ · จำนวนรายการค้างแยกตามประเภท · **ผลต่างคงเหลือ**
· รายการที่ยังอธิบายไม่ได้ (เรียงตามยอดเงิน) · รายการที่ต้องบันทึกเพิ่มใน GL

## Edge cases ที่เจอจริง

1. **WHT หลายอัตราปนกัน** — ลองทุกอัตรามาตรฐาน ไม่ใช่เดาอัตราเดียว
2. **ข้ามเดือน/ข้ามปี** — GL ลง 31 ม.ค. แต่เงินเข้า 1 ก.พ.
3. **โอนระหว่างบัญชีของกิจการเอง** — ปรากฏทั้งสองด้านในวันเดียวกัน อย่านับซ้ำ
4. **รายการกลับรายการ (reversal)** — ยอดติดลบ หรือคู่รายการกลับด้านในวันเดียวกัน
5. **รูปแบบวันที่ต่างกัน** — GL เป็น `DD/MM/YYYY` พ.ศ. แต่ statement เป็น `YYYY-MM-DD` ค.ศ.
6. **ยอดเท่ากันหลายรายการในวันเดียวกัน** — เสี่ยงจับคู่ผิดคู่ ต้องแสดงให้คนตรวจ
7. **ค่าธรรมเนียมรวมใน statement บรรทัดเดียวกับยอดโอน** — ยอดจะต่างเล็กน้อยเสมอ
8. **statement ที่ export มาไม่ครบงวด** — ตรวจว่าวันแรก/วันสุดท้ายครอบคลุมทั้งงวดก่อนเริ่ม

## ข้อจำกัดและสิ่งที่ผู้ใช้ต้องตรวจเอง

- **สถานะ "ตรง" คือเข้าเงื่อนไขที่ตั้งไว้ ไม่ใช่ถูกต้องทางบัญชี** — ต้องตรวจทุกบรรทัด
- **จับคู่ 1:1 อาจได้คู่ผิด** เมื่อมีหลายรายการยอดเท่ากันในวันใกล้เคียงกัน
- **จับคู่ 1:หลายรายการ เสี่ยง false positive สูงที่สุด** — ผลรวมที่บังเอิญเท่ากันเกิดได้จริง ต้องเปิดดูทุกกลุ่ม
- **การสันนิษฐาน WHT จากผลต่างเป็นการอนุมาน** — ต้องตรวจกับหนังสือรับรองหัก ณ ที่จ่ายตัวจริง
- ความคล้ายของชื่อใช้ประกอบการตัดสินเท่านั้น ไม่ใช่หลักฐาน
- การอ่าน PDF อาจได้ตัวเลขเพี้ยน — ใช้ `.xlsx`/`.csv` จากธนาคารถ้ามี
- **ไม่ตรวจจับการทุจริต** และไม่ตรวจว่ารายการที่จับคู่ได้มีเอกสารประกอบครบตาม พ.ร.บ.การบัญชี
- **ไม่บันทึกรายการปรับปรุงเข้า ERP ให้** — ผู้ทำบัญชีต้องบันทึกเอง
- ข้อมูลเดินบัญชีเป็นข้อมูลอ่อนไหว — ทำงานบนเครื่องสำนักงานเท่านั้น
